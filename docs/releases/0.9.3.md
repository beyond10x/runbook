# Runbook 0.9.3

A patch release of 0.9.2. The crate `runbook` links Loom `d8944d49`, in which a rejection gives an action a new
allowance of runs, and the story runbook uses it for `change.implement`. `runbook check` and
`scripts/check-bindings.sh` refuse by name what Loom refuses in a `budget`. The inspector does no work while no
page looks at it. Nothing is marked breaking. A source release at tag `0.9.3`; nothing is published to crates.io,
there is no binary asset and no interface is stable. `CHANGELOG.md` lists the changes with their sources. Read
`docs/releases/0.9.2.md` for the release this one follows.

### What this release holds

- **A rejection gives an action a new allowance of runs** (`docs/loom-bindings.md`, "The budget"). The crate
  `runbook` links Loom `d8944d49` (version 0.59.0; an ancestor of Loom's tag `0.60.0`), which replaces `c9b4c177`
  for all three Loom crates. A binding can say `budget.runs_per` (`case`, the default, or `rejection`),
  `budget.rework_limit` (a whole number from 1, default 2) and `budget.rework_on` (a map of evidence kind to
  results, written as `retry_when` is). With `runs_per: rejection` only the runs since the latest rejection count
  against `max_runs`. `bindings/sdc-story.yaml` binds `change.implement` with `max_runs: 3`, `runs_per: rejection`,
  `rework_limit: 2` and `rework_on` the rejections of `code_review` and `merge_approval`: a rejection by the review
  or the merge approval gives the writer three more runs, and the third rejection ends the run. A failed test run
  and a refused coverage use the runs of the window. In `runbook/Cargo.lock` only the Loom packages move.
- **A run that spends its runs ends `stuck`.** `RunsSpent` is no reason of a tree call, so `runbook run` ends such
  a run `stuck`, exit 3, cause `stuck`; the text is in the run log of the case (`docs/loom-run.md`, "The runs of an
  action are spent"). Tests with `sh` programs hold each of its two texts.
- **The bindings check knows the budget.** `runbook check` and `scripts/check-bindings.sh` refuse, in Loom's words,
  a `runs_per` that is neither `case` nor `rejection`, a `rework_limit` that is not a plain whole number from 1,
  `rework_limit` or `rework_on` without `runs_per: rejection`, `runs_per: rejection` with no result in
  `retry_when`, a malformed or empty `rework_on`, a `rework_on` pair that `retry_when` lacks, and the three members
  on an agent, open or copy action. It also refuses a bindings file with a `<<` merge key, a key that is a list or
  a mapping, or a tag that is not a core tag, and the script refuses an alias expansion past 100000 values or
  past 100 jumps for each event of the document. `scripts/check-bindings.sh --budget <root>` runs that check alone.
- **The budget step no longer ends the full check with a jq or yq error** on a document the exits step already
  refuses by name (a document that is no mapping, an `actions` that is no list, an entry or an `executor` that is no
  mapping). Six cases of `check_bindings_exits*` were red on the default branch since the Loom pin merge.
- **The stub of `sdc-node` numbers a person's repeated rejection** (`rework 2 of the rejection of ...`, from the
  second), so a second rejection with the same reasons no longer leaves the tree as the first rework left it. The
  ledger is `.sdc/rework-seen` in the work directory, opened as one regular file; `runbook parity` leaves that one
  path out by its own rule (`docs/parity.md`, `docs/driver.md`).
- **The inspector does no work while no page looks at it** (`ui/README.md`). No round runs without a connected
  page, a round reads only the run that page shows, a file whose size, times and inode are those of its last read
  is not read again, and the memory those texts hold is bounded (16 MiB). A page that is more than 1 MiB of output
  behind is dropped. The test option `--count-reads` exposes the counts at `GET /api/reads`; without it there is
  no such route.
- **For contributors:** the test step of `ui/` lists each spec as wide-only or both-sizes (`ui/test/lanes.mjs`) and
  its specs wait for an event instead of a fixed time, a check fails a sleep the list does not name; the shared
  source gate runs gates 0.1.27 (`.github/workflows/shared-gates.yml`).

### Breaking

None is marked. A bindings file with a `budget` member that Loom refuses at load is now refused by `runbook check`
and `scripts/check-bindings.sh` too, before a run.

### How to try it

There is no binary to download: build from the checkout. Each command below exists in this tree.

1. `scripts/install.sh --prefix <absolute dir>` installs into a directory you made (it builds in release mode,
   which takes minutes; `README.md`, "Try it").
2. `scripts/check-bindings.sh --budget <root>` checks the `budget` of the bindings under `<root>` and prints `pass`
   or `FAIL` lines; `runbook check` refuses the same forms.
3. Open the inspector on a directory of runs: `node server.mjs --runs <dir>` from `ui/` (`ui/README.md`); with no
   page open it reads nothing.
4. Check the release: `task release:check VERSION=0.9.3`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **No binary asset.** A user builds from a checkout with `scripts/install.sh --prefix <dir>`; the script is the
  source of an asset that does not exist yet (`docs/releasing.md`, "The binary").
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.9.2. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending`: alone, nine runs ended on Loom's 60 s bound
  before `change.implement` ran, at a host load of 45 to 112, so no run has shown the numbering of the stub at work
  (`docs/cycles-suite.md`). `rework_limit: 2` follows Loom's rules; no run has told 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom at the pin; no other form is claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader
  is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` still names the child binary of Loom `70b0e6e0`** and compares a
  library of `d8944d49` with it (`docs/loom-run.md`).
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/run_loop.rs`). A run of the daemon's stub
  runtime, in which nothing is executed, and a run directory an older `runbook` wrote have none, and the inspector
  shows them as it showed them before: "live state unknown" for a directory with `settings.json`, no end record and
  no `runner.json`.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends; the only file that grows while a step runs is under
  `work/.sdc/llm/`, a dot-directory the inspector never serves (`docs/loom-run-directory.md`).
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **Money caps are as in 0.8.0.** `runbook run` takes `--cap-micro-usd`, `--max-llm-calls` and
  `--max-wall-seconds` as required options (`docs/loom-run.md`); a file never sets or lowers the confinement level,
  and a cap in the settings file must equal the option.
- **A run started from the daemon's page or over MCP has no wall-time bound of its own.** The engine starts a run
  with no `max_wall_seconds` (`runbook/src/engine/calls.rs`, `run_settings`); a run ends by its outcome or by
  `cancel-run`. Its products are read on disk under the daemon's state directory (`runs/<run_id>/` and
  `workspaces/<run_id>/`, `docs/daemon-api.md`): no tool or route serves them yet.
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count read
  from the tree or from a command named above. The measurements of the inspector's idle work in `CHANGELOG.md` and
  `ui/README.md` were made on the build host and are in no record of `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
