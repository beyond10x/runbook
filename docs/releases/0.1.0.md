The first release of the SDC prototype: eight Canon `protocol/1` protocols for the cycle from an idea to a built, tested product, a ninth for one bug fix, the driver that runs them, and a live view of a run. A source release at tag `0.1.0`; nothing is published to crates.io (`publish = false` in the three crates) and no interface is stable. Paths are relative to the repository; a figure marked "run record" comes from `runs/`, which is not in git, and is stated as recorded there (`docs/trial-3.md` is the account of trial 3).

### What works

- Nine protocols, `format: protocol/1`, composed with child cases: the eight of the cycle, one case per stage (idea `sdc`, intake, direction, epic, spec, plan, story, release), and `sdc-bugfix` (`protocol/*.protocol.yaml`, `docs/protocol-notes.md:3-16`, `AGENTS.md`). The stage is derived from facts, never from a stored phase (`docs/phases.md:3-6`).
- The driver `sdc-drive` (`driver/`): reads Canon's `canon-decision/1`, runs the tool bound to one admissible action, records `canon-evidence/1`, evaluates again; an LLM is only one action's executor (`docs/driver.md:3-6`).
- Autopilot: a decider model takes the place of a person and is final (`SDC_DECIDER_ESCALATE=final`; `SDC_AUTONOMY=A5` or `scripts/run-trial.sh <run> "<idea>" --autopilot`); it refuses `SDC_DECIDER=person` (`docs/autonomy-levels.md:449`).
- A review node as a model call: `change.review` is an LLM call of class REVIEW, a fresh session with read-only operations that replies through a response schema and not by writing a file, checked by program, and admitted only after `tests.pass` (`docs/driver.md`, "The code review"; `driver/examples/sdc/sdc-story.bindings.json`, producer `llm-review`). The reply fix is `50d90b9` (`49b0a87`).
- Rework after a rejected approval: the rejection is recorded as `canon-evidence/1` with result `rejected`, the writer runs again with the reasons, the approval is asked again; the third rejection ends the run `rework_spent` (`docs/driver.md`, "A rejected approval"; `docs/autonomy-levels.md:462-467`). The reject and cap routes are audited in `docs/reject-routes.md`.
- A run ends by rule: a terminable root is closed by `rule:autopilot` and the decider is asked nothing; a stop the decider cannot take is written by `rule:autopilot` with a cause (`docs/driver.md`, "The close in autopilot").
- A finding re-raised after a decision stops the run: a trace finding the decider decides as a constraint is applied, and a second raise ends the run `finding_reraised` instead of consuming the decider's budget (`6c7ba78`, `b4aa0d1`; cycle `trace-reraised`, `scripts/run-finding-cycles.sh`).
- Model per node class: `SDC_LLM_MODEL_WRITER`, `_IMPLEMENT`, `_REVIEW`, `_OTHER`, `_DECIDER`, else `SDC_LLM_MODEL`, else the binding's (`docs/driver.md`, "Model per node"). `spec.review` is still a program stub (same place). The `claude-cli` adapter is hermetic and every node class has an explicit default effort, recorded per run (`f747085`, `6c1f649`; `docs/driver.md`, "Hermetic `claude-cli` adapter").
- One bug fix, red first, as its own protocol `sdc-bugfix`: dissect the report, write a reproducing test that is red, fix, run the tests, update the story, run the gate (`docs/bugfix.md`; `scripts/run-trial.sh <run> --bugfix <seed dir>`). On this release: the protocol (1,024 states, `docs/bugfix.md`), the `sdc-bugfix` binary and the runner, at `d2e4896`. Run records of nine runs on four seeded bugs, on branch `impl/bugfix-cycle`: eight closed `fixed` (Sonnet and Haiku, 3 to 5 model calls, 0.009 to 0.17 USD, 43 to 183 s as recorded by the trial session); one closed `not_fixed`, a defect of the red check, fixed on that branch in `99238c0`. Of that branch only `d2e4896` is in this release: `99238c0` and the four scripted bug-fix cycles (`e108d5e`) are not.
- The requester-side decider: a requester agent, principal `decider:requester`, decides the requester-side classes from a goals document checked by `sdc-goals` (`docs/requester.md`, `driver/examples/sdc/tools/decider.sh`, `goals/`).
- The live view `ui/`: where each case stands, why, what is admissible, who acted, run metrics, live while a run writes the store (`ui/README.md`).
- Scripted end-to-end checks: `scripts/run-finding-cycles.sh` has 68 expected cycles and a pending list of 7 routes not built yet, which never fails the script (the `expected` and `pending` arrays of the script, counted by evaluating them); `scripts/evaluate-cases.sh` evaluates 52 situations in 12 fixture cases under `cases/` (`expected.json` files).
- Canon's static analysis (`canon simulate`) of the protocols, triaged: 71 findings on the eight protocols, 5 of them real dead ends (1 stuck state, 4 cycles) (`docs/simulate-findings.md`).

### Limits

- Earlier runs' decisions were taken with the host's settings: until `f747085` the decider's model call loaded the host user's Claude Code setup (the `init` event of `runs/trial-3-strong-2/decider/001-q1/events.jsonl` lists 14 tools, 11 plugins, 60 skills and the host's output style) and took its effort level from the host's settings, which the runs do not record. The decisions of all seven passes are not reproducible on another machine as recorded. The hermetic adapter and an explicit default effort per class are in this release; no pass ran on them.
- Before `50d90b9` the first real code review stopped every run: three runs from `main` at `8db4b93` with the real review node (`trial-3-strong-3`, `trial-3-strong-4`, `trial-3-mixed-7`) stopped `stuck` at their first `change.review` call with the reply file `out/review.json` unreadable. Fixed in this release (`50d90b9`); the runs through the fixed review node that passed are `trial-3-strong-6` and `trial-3-strong-5` above, whose tree is `main` plus that one fix branch, not this release's tree: the released tree adds the hermetic adapter, the effort per class, the re-raise fix, the bug-fix protocol and the audit, and its decider was not hermetic.
- Five of the six passes ran on `trial/3b` at `acd6f12` (`main` at `32265be` plus fixes that are all on `main` since), with the review step still a stub: no review model call ran in them.
- Three batch passes (`strong-1`, `strong-2`, `opus-1`) had no merge rejection. Rejections of `merge.approve` with rework occurred in two (`mixed-6`, `haiku-7`) and reviewed rejections in `strong-6` (2) and `strong-5` (4). The release reject route did not occur in a pass: it ends `not_delivered`.
- Nobody started the delivered product; `haiku-6` and `mixed-5` show that a story set can pass every merge and still miss the idea (`docs/trial-3.md`).
- Known faults, not fixed in this release: the decider's principal is named `decider:haiku` whatever model decides (`driver/examples/sdc/tools/decider.sh:5`, kind `haiku`; run record `trial-3-strong-1`: kind `haiku`, model Opus); the driver's "LLM calls so far" counts every started action of a binding with `llm`, including runs that called no model (`driver/src/main.rs:1033-1043`, printed by `scripts/run-trial.sh:291,712`; `docs/trial-2.md:519`: 18 calls in `llm-calls.jsonl`, 19 counted).
- The bug-fix runs ran on `impl/bugfix-cycle` and not on this release's tree: the red-check defect fixed in `99238c0` is still in this release, and no scripted cycle covers `sdc-bugfix`.
- The driver's runtime parts are a temporary copy of what the Loom runtime must provide (`AGENTS.md`, `docs/layers.md:51`, `docs/driver.md:43-45`).
- Release and operate are being split out of the cycle (branch `proto/cycle-ends-delivered`, `c0ebccb`, not in this release); that is not in this release.
