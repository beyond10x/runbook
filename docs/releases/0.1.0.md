The first release of the SDC prototype: eight Canon `protocol/1` protocols for the cycle from an idea to a built, tested product, the driver that runs them, and a live view of a run. A source release at tag `0.1.0`; nothing is published to crates.io (`publish = false` in the three crates) and no interface is stable. Paths are relative to the repository; a figure marked "run record" comes from `runs/`, which is not in git, and is stated as recorded there (`docs/trial-3.md` holds the full account).

### What works

- Eight protocols, `format: protocol/1`, one case per stage, composed with child cases: idea (`sdc`), intake, direction, epic, spec, plan, story, release (`protocol/*.protocol.yaml`, `docs/protocol-notes.md:3-16`). The stage is derived from facts, never from a stored phase (`docs/phases.md:3-6`).
- The driver `sdc-drive` (`driver/`): reads Canon's `canon-decision/1`, runs the tool bound to one admissible action, records `canon-evidence/1`, evaluates again; an LLM is only one action's executor (`docs/driver.md:3-6`).
- Autopilot: a decider model takes the place of a person and is final (`SDC_DECIDER_ESCALATE=final`; `SDC_AUTONOMY=A5` or `scripts/run-trial.sh <run> "<idea>" --autopilot`); it refuses `SDC_DECIDER=person` (`docs/autonomy-levels.md:449`).
- A review node as a model call: `change.review` is an LLM call of class REVIEW, checked by program, and is admitted only after `tests.pass` (`docs/driver.md:462-472`; `driver/examples/sdc/sdc-story.bindings.json`, producer `llm-review`). See Limits for its state in real runs.
- Rework after a rejected approval: the rejection is recorded as `canon-evidence/1` with result `rejected`, the writer runs again with the reasons, the approval is asked again; the third rejection ends the run `rework_spent` (`docs/driver.md:487-500`, `docs/autonomy-levels.md:462-467`).
- A run ends by rule: a terminable root is closed by `rule:autopilot` and the decider is asked nothing; a stop the decider cannot take is written by `rule:autopilot` with a cause (`docs/driver.md:524-545`).
- Model per node class: `SDC_LLM_MODEL_WRITER`, `_IMPLEMENT`, `_REVIEW`, `_OTHER`, `_DECIDER`, else `SDC_LLM_MODEL`, else the binding's (`docs/driver.md:366-372`). `spec.review` is still a program stub (same lines).
- The requester-side decider: a requester agent, principal `decider:requester`, decides the requester-side classes from a goals document checked by `sdc-goals` (`docs/requester.md`, `driver/examples/sdc/tools/decider.sh`, `goals/`).
- The live view `ui/`: where each case stands, why, what is admissible, who acted, run metrics, live while a run writes the store (`ui/README.md`).
- Scripted end-to-end checks: `scripts/run-finding-cycles.sh` runs 56 expected cycles on this tree (the `expected` array of the script, counted by evaluating it); `scripts/evaluate-cases.sh` evaluates 45 fixture cases under `cases/` against their `expected.json` (45 passed on this tree).

### Trial 3, 2026-11-21 (run records, `docs/trial-3.md`)

The to-do list idea run unattended (`--autopilot`) to a closed, delivered tree: status `closed`, outcome `operating`, closed by `rule:autopilot`, exit 0, replay of the event log matching, nobody waited on. Five of the eight runs of the batch tree passed:

| Run | Work nodes | Decider | Wall | Cost | Merge rejections (all reworked, then approved) |
|---|---|---|---|---|---|
| `trial-3-strong-2` | Sonnet | Opus | 454 s | 3.00 USD | 0 |
| `trial-3-strong-1` | Sonnet | Opus | 473 s | 2.93 USD | 0 |
| `trial-3-opus-1` | Opus | Haiku | 1,662 s | 5.09 USD | 0 |
| `trial-3-mixed-6` | Sonnet for spec, plan, build; Haiku for the other nodes | Haiku | 2,295 s | 1.86 USD | 2, `list.offline` |
| `trial-3-haiku-7` | Haiku | Haiku | 2,709 s | 1.00 USD | 1, `todo.sync` |

Not passed: `trial-3-haiku-6` (all Haiku) closed by itself as `not_delivered`, the decider withholding an incomplete product; `trial-3-sonnet-1` stopped on the decider's call budget (`decider_budget_spent`, 20 calls). `trial-3-mixed-5`, started on an older tree, also closed `not_delivered`. Earlier attempts are in `docs/trial-2.md` and `docs/trial-3.md`.

### Limits

- On this release a real run with default settings stops at the first code review: three runs from `main` at `8db4b93` with the real review node (`trial-3-strong-3`, `trial-3-strong-4`, `trial-3-mixed-7`) stopped `stuck` at their first `change.review` call, the reply file `out/review.json` unreadable (run record: `llm/NNN-change.review/review-check.err`; the trial's diagnosis is that the review model has read-only access and cannot write it). No run with the review node has passed.
- On this release the decider's model call is not hermetic: in every trial run it loaded the host user's Claude Code setup (the `init` event of `runs/trial-3-strong-2/decider/001-q1/events.jsonl` lists 14 tools, 11 plugins, 60 skills and the host's output style), and its effort level came from the host's settings, which the run does not record. The decisions of the five passes are not reproducible on another machine as recorded. A fix is on branch `feat/effort-per-class` (`6c1f649`: hermetic adapter, an explicit default effort per node class); it is not on `main` when this release was prepared.
- The five passes ran on a side branch, `trial/3b` at `acd6f12` (`main` at `32265be` plus fixes that are all on `main` since), with the review step still a stub: no review model call ran in any pass.
- Three passes (`strong-1`, `strong-2`, `opus-1`) had no merge rejection. Rejections of `merge.approve` with rework occurred in two (`mixed-6`, `haiku-7`). The release reject route did not occur in a pass: it ends `not_delivered`.
- Nobody started the delivered product; `haiku-6` and `mixed-5` show that a story set can pass every merge and still miss the idea (`docs/trial-3.md`).
- Known faults, not fixed in this release: the decider's principal is named `decider:haiku` whatever model decides (`driver/examples/sdc/tools/decider.sh:5`, kind `haiku`; run record `trial-3-strong-1`: kind `haiku`, model Opus); the driver's "LLM calls so far" counts every started action of a binding with `llm`, including runs that called no model (`driver/src/main.rs:1033-1043`, printed by `scripts/run-trial.sh:291,712`; `docs/trial-2.md:519`: 18 calls in `llm-calls.jsonl`, 19 counted).
- The driver's runtime parts are a temporary copy of what the Loom runtime must provide (`AGENTS.md`, `docs/layers.md:51`, `docs/driver.md:43-45`).
- Canon's static analysis (`canon simulate`) of the eight protocols lists 71 findings, 5 of them real dead ends (1 stuck state, 4 cycles). The triage is `docs/simulate-findings.md` on branch `plan/simulate-triage` (`d67aec5`), not on `main` when this release was prepared.
- Release and operate are being split out of the cycle (branch `proto/cycle-ends-delivered`, `c0ebccb`, not on `main`); that is not in this release.
