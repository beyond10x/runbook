# Runbook 0.5.0

A minor release of 0.4.1, the same day. `runbook run` runs a case in the process of the command with
Loom linked as a library, `runbook test` runs a tree suite, and the command `loom-run` is gone. The
decider and every model node are Rust programs. A source release at tag `0.5.0`; nothing is published
to crates.io and no interface is stable. `CHANGELOG.md` lists the changes with their sources. Read
`docs/releases/0.4.1.md` for the release this one follows.

### What this release holds

- **`runbook run <runbook>` runs in process.** It is the code that was `runbook loom-run`, and the
  subcommand `loom-run` is gone. Loom is a library of the process: no `b10x-loom`, `canon` or
  `sdc-drive` process starts, only the bound programs of the bindings. `--loom <binary> --loom-sha256
  <hex>` still runs the child way. The runbook id is the positional argument; `--bindings`,
  `--protocols` and `--root-protocol` default to what the asset root holds, `--case` to `IDEA-1`.
  `--intake <file|->` takes the idea's text (`--idea` and `--in-process` are gone). Exit codes, run
  directory files and events are what `loom-run` wrote (`docs/loom-run.md`, `docs/cli.md`).
- **The options of the old launcher are built, except the replay.** `--dry` runs the stub cycle with
  every model node on the adapter `dry`, prints every command a call would have run and costs 0;
  `--bugfix <seed dir>` and `--bugfix-ticket <file>` open a bug-fix case; `--goals <file>` copies the
  requester's goals document to `work/goals.yaml`; `--watch` starts `sdc-watch` as the run's child and
  ends it with the run; `--conformance observe` writes `oracle.json` after a run that ended closed
  and decides nothing (`docs/loom-run.md`, `docs/bugfix.md`, `docs/fs-changes.md`,
  `docs/conformance.md`).
- **`runbook test <suite file> --confinement <local|substrate>`.** It runs the cycles of a
  `loom.tree-suite/1` file through Loom's suite runner in process, prints one line per cycle, the ten
  slowest and `N of M as expected, P pending`, and exits 0 only when every cycle that ran is as
  expected (`docs/cli.md`, "`runbook test`"). `cycles/tree-suite.yaml` states cycles of
  `cycles/suite.yaml` for it; `task test:cycles-loom` runs it.
- **The decider runs in Rust.** The model, rule and requester decider run inside the runner
  (`runbook/src/loom_run/decider/`) and no longer start `bindings/tools/decider.sh`, `jq`, `yq`,
  `rsync` or `bash`; the only program a decision starts is the adapter of `decider.adapter`. With
  `decider.requester: true` and `--goals` it answers the requester-side classes
  (`docs/loom-run-decisions.md`).
- **Every model node is `sdc-node`.** All 14 model nodes of `bindings/*.yaml` start the program
  `sdc-node`, including `change.implement`; `bindings/tools/llm-node.sh` serves the old driver only
  and refuses Loom mode with exit 126. `change.review` runs under Loom through `sdc-reply`.
- **`sdc-experiment run` starts runs only with `runbook run`** (`runner: loom`; `runner:
  free-agent` is unchanged). `stop` writes the stop record and stops the run's systemd unit.
- **Pins.** Loom `5b3142c7` and Canon 0.11.0 (`driver/canon-pin.json`, `protocol/simulate/CANON_REV`)
  are linked as libraries; `runbook serve --runtime loom` runs the daemon's runs through Loom's
  library calls (`docs/engine.md`).

`runbook --version` prints 0.5.0.

### Breaking

- The command `runbook loom-run` is gone; `runbook run <runbook>` replaces it. `--idea` and
  `--in-process` are gone with it: `--intake` takes the idea, and Loom is a library unless `--loom`
  and `--loom-sha256` are given.
- `sdc-experiment run` refuses a variant with `runner: sdc` or with no `runner`, a record of the old
  driver, with one line that names `runner: loom`. `check` and `report` still read such a record.
- `sdc-experiment stop` takes no `--builds-dir`.
- The setting `decider.program` is refused (`runbook/src/loom_run/settings.rs`): the decider is not a
  program of the bindings copy.
- A reject of a question or of a finding by the decider is an invalid reply
  (`runbook/src/loom_run/decider/validate.rs`).

### How to try it

Build with `cargo build --bins` in `driver/` and `cargo build --bin runbook` in `runbook/`. Each
`--help` below was run on this tree.

1. `runbook --version` prints 0.5.0; `runbook run --help` and `runbook test --help` print the options.
2. Run one cycle of the tree suite: `task test:cycles-loom ONLY=stub-cycle`. It builds first, and the
   whole file is a slow lane that is not part of `task check`.
3. Read how a dry run is made, and what it prints, in `docs/loom-run.md`, "A dry run".
4. Check the release: `task release:check VERSION=0.5.0`, and the experiment records with
   `sdc-experiment check --all`.

### Numbers

- The bindings hold 14 model nodes, all started through `sdc-node`.
- `cycles/suite.yaml` lists 130 cycles. `cycles/tree-suite.yaml` holds 54 of them: 36 converted and 18
  pending, which leaves 76 not converted (`docs/cycles-suite.md`, "Totals and time").
- Six tests are `#[ignore]`d; each names a difference between the runner and the old driver (see
  Limits).
- The test steps were not run for this note; no test count or test time is claimed here.

### Limits

- The replay options of `runbook run` are refused. `--recorded` exits 64 with `--recorded is not built
  yet`; `--on-divergence`, `--live-adapter`, `--live-cap`, `--inject`, `--set`, `--take-recorded` and
  `--source-tree` exit 64 with `<option> needs --recorded <source>` without it.
- No measured run of an evaluation has used this tree, and the release claims no measured change. The
  last records of runs through Loom (`experiments/parity-loom-strong-3.yaml`) were made with
  `runbook loom-run` on an earlier tree and decide nothing; no parity verdict between the driver and
  Loom exists.
- The effort per node class of a settings file (`efforts.<class>.effort`, `SDC_LLM_EFFORT_<CLASS>` of
  the old driver) has no way into `sdc-node`, which takes the class default of
  `bindings/tools/node-classes.json`; this holds for `--dry` as well (`docs/cycles-suite.md`, row
  `efforts`).
- The rule approver (`SDC_RULE_APPROVALS`, claims of the position), the rework cap of the old driver
  and the end by rule `withhold` are not in the runner: Loom's output holds no claim values and Loom
  has no such steps (`docs/loom-run-decisions.md`).
- Six tests are ignored because the runner differs from the old driver (`git grep -n '#\[ignore' --
  runbook/tests/loom_run/decisions.rs runbook/src/loom_run/decider/tests.rs`): `approved_on_checks`
  after three invalid replies, a rejection that names its case with exit 6, the decider's answer to a
  release at A3, a close at A5 taken by rule, a close at A3 asked of the decider, and a stop reason
  with no person.
- Of the 130 cycle entries 36 are converted to the tree suite and 18 are pending (5 wait for a Loom
  story, 13 run and still fail); 76 are not converted. The whole file is a slow lane; neither it nor
  `scripts/run-finding-cycles.sh` was run on this tree for this note.
- The daemon (`runbook serve`) runs the stub runtime unless `--runtime loom` is given; `stub` is the
  default (`runbook/src/serve.rs`, `docs/engine.md`). The Loom runtime is run through the slow lane
  `task test:engine-real`, not by the gate.
- The old driver (`sdc-drive`, `scripts/run-trial.sh`) is still in the tree; `sdc-experiment run` no
  longer starts it, and no check of this note ran it.
- `task check:ess-suite:slow`, the byte comparison of a new synthesis with the committed suite, was
  not run for this release; the fast digest check is part of `task check:ess-generated`.
- Under Loom the exits 69 and 70 are recorded as `failed` (`bindings/PENDING.md`).
- The 26 files in `driver/unreferenced-keep.txt` are unexamined.
- Every limit of 0.3.1 that this note does not change stands.
