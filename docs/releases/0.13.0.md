# Runbook 0.13.0

A minor release of 0.12.0. Three changes are marked breaking: a daemon run whose decider kind is `model` reaches its
model only through the daemon's relay, a daemon run whose last program failed ends `failed: step ...` instead of
`runtime-failure`, and the `runbook` plugin denies a Claude Code session's Agent and Workflow calls. The daemon
declares named model routes, starts a run only on a route that can answer, relays and books every model call of a run
on a route, takes a delegation and lists what a delegation may name; its run page watches a live run. A source release
at tag `0.13.0`; nothing is published to crates.io, there is no binary asset and no interface is stable.
`CHANGELOG.md` lists the changes with their sources. Read `docs/releases/0.12.0.md` for the release this one follows.

### Breaking changes

- **A daemon run whose decider kind is `model` reaches its model only through the daemon's relay.** Its decider's
  adapter gets the run's route file in `RUNBOOK_ROUTE_FILE`, no longer the gateway file in `SDC_GATEWAY_FILE`, and on
  a daemon whose listener is not loopback the relay is not served and such a run does not start, where in 0.12.0 it
  started with the gateway's address and token. The remedy: an adapter of another repository reads
  `RUNBOOK_ROUTE_FILE`, and a daemon that runs model deciders listens on loopback (`docs/engine.md`, "A gateway").
- **A daemon run whose last program failed ends `failed: step <action> <end>`.** A run whose last program ended with an
  exit its bindings list as an error, a signal, its timeout or no exit status, and left the tree with nothing to do,
  ends with that outcome and the event `runbook.step-failed`, where in 0.12.0 it ended `runtime-failure` "the tree is
  stuck". The remedy: a client that reads a run's outcome takes `failed: step ...` as a failed run
  (`docs/daemon-api.md`).
- **The `runbook` plugin denies every Agent and Workflow call of a Claude Code session that enables it** and starts
  `runbook mcp` as its MCP server, where in 0.12.0 it held skills only. The remedy: a session that runs sub-agents of
  its own does not enable the plugin; the Codex manifest lists the skills only, as before (`plugin/README.md`,
  "Delegation through Runbook").

### What this release holds

- **Model routes** (`docs/model-routes.md`; `docs/daemon-api.md`, "Model routes" and "The route of a run"). The
  daemon's `runbook.toml` declares `[gateways.<name>]`, `[routes.<name>]` (`managed`, `hosted` or `local`) and
  `[route_policy]`; the view `routes` and the MCP tool `list_routes` list each route with its status. A run names its
  route (`model_route`, `model_routes.<role>`, `runbook run --model-route`), else a runbook's route entries
  (`bindings/<runbook>.routes.yaml`, `runbook.routes/1`) or `[route_policy] default` choose it, and a submit names
  what refused it (`422 route-refused`). A run starts only on a route that can answer: a model that is not callable
  holds it in `WaitingForRoute` up to the route's `start_wait_seconds`, then it ends `stopped: route`. A managed route
  is woken only behind a daily wake cap (`wake_daily_cap_micro_usd`, `wake_cost_micro_usd`).
- **The relay books every model call of a run on a route** (`docs/daemon-api.md`, "The relay of a run's model calls").
  On a loopback listener the daemon serves `/daemon/relay/<run>/v1/messages`, `/v1/chat/completions` and
  `/v1/responses`; a run gets a token of its own and a route file, the relay adds the gateway's token, and each call is
  one ledger line and one event `runbook.model-call` with its route, alias, tokens (the prompt cache included) and
  cost. A call the client recovers from no longer ends the run by itself; the run ends as its step ends.
- **The daemon takes a delegation** (`docs/daemon-api.md`, "A delegation"; `docs/mcp.md`). `POST
  /daemon/commands/delegate`, the MCP tool `delegate` and `runbook delegate` run a piece of agent work on a route:
  with a named runbook, classified to one of the catalog's runbooks, as a protocol built for it, or as the free run.
  The view `catalog` (`describe_catalog`, `runbook catalog`) lists the routes, the runbooks and the terms of a
  delegation; `delegation-result` answers the result, the calls and the cost.
- **A Claude Code session delegates through Runbook** (`plugin/README.md`, "Delegation through Runbook"). The plugin's
  hook denies Agent and Workflow calls with a reason that names the `delegate` tool and the session's route; a headless
  session against a stand-in model delegates end to end (`runbook/tests/daemon/plugin_session.rs`).
- **The daemon's run page watches a live run** (`ui/README.md`; `docs/daemon-api.md`, "The web UI"). The centre lists
  the run's steps with the step in flight and its duration counting, the side panel holds Products, Events and, when
  the view `run-metrics` answers, Metrics; the sidebar draws the run's case tree (view `cases`); the header names the
  run's route, and the Routes view lists the daemon's routes. `?run=<run id>` opens a run after a reload.
- **The daemon serves more of a run.** The views `products` and `product` (MCP `list_products`, `read_product`) read
  the run's `work/` directory with links, second names and dot names refused; `run-metrics` answers a run's steps,
  calls, tokens and cost read from its events; runs of one `serial_key` run one at a time in submit order; MCP opens
  and closes sessions; a person action's question and options can come from its case (`decision-request.json`).
- **A command of a program step has its own deadline, retry and poll** (`docs/loom-bindings.md`, "A command's
  deadline, retry and poll"): the helper `sdc-command`, with the example runbook `examples/long-step/`.
- **`runbook` links Loom 0.62.1** (`112a97e1`, tag `0.62.1`; replaces `ed644a4d`, Loom 0.61.0). A bindings file may
  name `workspace: read_write`; no bindings file here names it.
- **The runbook test step fits its budget on the forge**, and `task check:names` refuses an added line that names a
  person, an organisation or a session (`docs/forge-gate.md`; `AGENTS.md`, "Rules").

### How to try it

There is no binary to download: build from the checkout. Each command below exists in this tree.

1. `scripts/install.sh --prefix <absolute dir>` installs into a directory you made (it builds in release mode,
   which takes minutes; `README.md`, "Try it").
2. `runbook serve --principal agent:<id> --runtime loom` with a `runbook.toml` that declares a route, then
   `runbook catalog` and `runbook delegate --route <route> <request-file>` (`docs/daemon-api.md`, "A delegation").
3. Check the release: `task release:check VERSION=0.13.0`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **No binary asset.** A user builds from a checkout with `scripts/install.sh --prefix <dir>`; the script is the
  source of an asset that does not exist yet (`docs/releasing.md`, "The binary"). The static musl archive (story
  `static-musl-release`) waits for a Loom release: the musl build stops in the substrate crate that the pinned Loom
  reaches, and the release workflow is not on `main`.
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.12.0. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The cases view can show the open case of a run ended by a cap as `Stuck`.** In a daemon run each Loom call runs
  one step, so a case's last stop is nearly always the one-step `BudgetSpent` line, and a run the daemon ends by its
  spend or call cap lists its open case as `Stuck`. Inferred from the code, not observed in a run; the defect is filed
  as the story `a-case-of-a-run-ended-by-a-cap-is-not-shown-stuck` and is open.
- **A run on a route works at `--confinement local` only.** At `linux` a delegation on a route fails at once,
  `env: 'sdc-node': No such file or directory`, exit 127, from a prefix and from a checkout; the story
  `route-runs-at-linux-confinement` (draft) waits.
- **The relay is served on a loopback listener only.** On any other listener a run on a route does not start
  (`docs/daemon-api.md`, "The relay of a run's model calls").
- **Runbook does not read the gateway's `cost_usd`.** A call's cost is its route's declared prices, else the call is
  booked at its reservation with `cost_known: false` (`docs/model-routes.md`). The Routes view shows no calls and no
  booked spend per route: the daemon serves no count of them.
- **A generated protocol of a delegation runs only the daemon's agent node.** The programs and child runbooks of the
  catalog are not built into it (`docs/model-routes.md`, section 9).
- **The default spec check tests that a reference is there, not that the spec says what the fix does.** It reads the
  whole description, so a code path under the spec directory (a test tree named `spec/`) counts; name another
  directory with `--spec-dir` (`docs/bugfix.md`).
- **The default description writer is a program and reads no feedback.** Sent back after a refusal it writes the same
  description unless its inputs changed; `sdc-check-routes` lists this as a `not-handed` finding of `handback.describe`,
  and a model writer bound in its place gets the refusal line (`docs/reject-routes.md`).
- **A gateway of `runbook run` works at `--confinement local` only.** Under `substrate` a bound program has no network,
  so the runner refuses a gateway there by the name `gateway`. `llm-adapter-metaharness.sh` cannot take one (it
  removes every `ANTHROPIC_*` variable and starts its own proxy) and ends with exit 127 when it is given one. With an
  `http://` address at a host that is not loopback the token travels in clear text; the choice is the user's
  (`docs/loom-run.md`).
- **The forge runs no UI specs.** On 2 CPUs the UI step does not end inside the 120 s step budget (550 to 587 of 611
  tests were done when the bound ended it, measured on the build node), so a UI change is checked by the local gate
  only until the test-budget defect of `test:ui` is fixed (`docs/forge-gate.md`).
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending` (`docs/cycles-suite.md`); no run has told a
  `rework_limit` of 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom when they were measured, at `d8944d49`; no measurement of them at a later pin is recorded, no other form is
  claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` compares a library of `112a97e1` with the child binary of Loom
  `70b0e6e0`** (its sha256 is pinned in `runbook/tests/loom_run/slow.rs`); no `b10x-loom` of `112a97e1` was built for
  it (`docs/loom-run.md`).
- **The recorded cycles run in `docs/cycles-suite.md` is at Loom `d8944d49`.** The file's last record of the whole
  suite is 55 cycles, `40 of 40 as expected, 15 pending`; the tree holds 56 cycles and the file has no record of a run
  of all of them.
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/in_flight.rs`). A run of the daemon and a run
  directory an older `runbook` wrote have none, and the inspector shows them as it showed them before.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends (`docs/loom-run-directory.md`). The daemon's run page shows the step
  in flight and its duration, not its output.
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **A run with no money cap named is not limited in money.** `runbook run` and `sdc-experiment` start a run with
  no `--cap-micro-usd` and no `--max-llm-calls`; the daemon with `--runtime loom` is the exception, it requires its
  caps and their ceilings (`docs/loom-run.md`, `docs/daemon-api.md`). A call of unknown cost in a run that names no
  spend cap books nothing. In a run opened with a model node the printed command of a handoff runs as printed under
  a named cap too, so several steps spend from one reservation before the cap is looked at again; the story
  `handoff-under-a-named-cap-runs-one-step-at-a-time` (proposed) is the bound for it.
- **The daemon serves no evidence records and no action output of a run.** Its files under `work/` are served by the
  views `products` and `product`; the rest is read on disk under the daemon's state directory (`docs/daemon-api.md`).
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count
  read from the tree, from a command named above or from the forge's log of a run named above. The times in
  `CHANGELOG.md` and `docs/forge-gate.md` were measured on the build host or the forge and are in no record of
  `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
