# Runbook 0.10.0

A minor release of 0.9.3. Two changes are marked breaking: the daemon has no built-in confinement, and `runbook run`
has no money limit built in. A `runbook.toml` supplies the defaults of `runbook run` and names the directories
runbooks are loaded from; a daemon run is never unbound, takes an autonomy level and a decider, records the step in
flight and takes its runbook at submit; the daemon drains on its stop signal. A source release at tag `0.10.0`; nothing
is published to crates.io, there is no binary asset and no interface is stable. `CHANGELOG.md` lists the changes with
their sources. Read `docs/releases/0.9.3.md` for the release this one follows.

### Breaking changes

- **The daemon has no built-in confinement.** A client that submits without `confinement` to a daemon that states no
  default (no `--default-confinement`, no `confinement` in the `runbook.toml` it reads) is refused `400` by name and
  nothing is written; before, such a submit ran at `linux`. The remedy: start the daemon with
  `--default-confinement linux` (or `local`), or name `confinement` in the submit.
- **`runbook run` has no money limit built in.** `--spend-ledger`, `--cap-micro-usd` and `--max-llm-calls` are each
  optional, alone and together, for every run: a run that names none opens no ledger, refuses nothing and applies no
  limit. A named cap stops the run when reached, as before (exit 4 for the spend cap, exit 6 for the call cap), and a
  named 0 means spend nothing. What is gone, and a script that read it reads nothing now: the usage error (exit 64)
  for a missing `--cap-micro-usd`, `--max-llm-calls` or `--spend-ledger` of a run with a model node, the refusal by
  name of a run without a model node under `--confinement local` without caps (exit 2, `NO_NETWORK_LEVELS`), and
  `stopped: model call` (exit 13, cause `model_call_without_model_node`). The decider has no built-in limits either:
  one that names no `decider.max_calls` or `decider.max_budget_usd` is not limited (the old defaults were 20 calls and
  0.25 USD per call). The entry gives no one-line remedy: a script that relied on the refusal names the caps it wants
  (`docs/loom-run.md`, "The money options"). `--max-wall-seconds` stays required and unchanged.

### What this release holds

- **`runbook.toml` carries the defaults of `runbook run`** (`docs/loom-run.md`, "Where a value comes from"). The file
  is found by `--config`, `RUNBOOK_CONFIG`, a walk up from the working directory, then the user's configuration
  directory (the first hit wins, no two files are merged); `--no-config` and `RUNBOOK_NO_CONFIG` read none. A value
  comes from an option, a member of `--settings`, the file, or a built-in default; the confinement and the wall time
  have no built-in default, and no file value lowers an option. `--run`, `--runs-dir` and `--settings` are no longer
  required. `runbook config` prints every effective value with its origin and `runbook init` writes a starter. The
  file is refused by key, never with a line or a value.
- **A `runbooks = [...]` list names the directories runbooks are loaded from** (`docs/loom-run.md`, "Runbook
  directories"). `runbook list`, `run`, `serve`, `check` and `doctor --for` resolve a name through one function over
  those directories in order and the built-in set last. The fixed list of startable names is gone.
- **A daemon run is never unbound** (`docs/daemon-api.md`, "Caps of a run"). `runbook serve --runtime loom` requires
  `--max-wall-seconds`, `--max-llm-calls` and `--cap-micro-usd` and takes a ceiling for each; a submit names its caps
  in `settings` up to the ceiling. Each run holds its own caps and a run at a cap ends as `runbook run` does.
- **A binding names the per-call budget of its programs.** The member `max_budget_usd: <number>` of a program action
  (or at the top of a bindings file) is the budget that action's programs reserve, so a runbook whose programs call no
  model is no longer refused at submit (`docs/loom-bindings.md`, "The per-call budget of a program").
- **A daemon run takes an autonomy level and a decider.** `submit_run` has optional `autonomy` (`A0` to `A5`) and
  `decider`, and `runbook serve --autonomy` and `--decider` give the defaults; each answer names who gave it
  (`docs/engine.md`, "Autonomy and a decider"). The daemon states the level of a submit that names none
  (`--default-confinement`, see Breaking changes).
- **A daemon run records the step in flight and takes its runbook at submit.** The event `runbook.action-started` and
  the member `step_in_flight` of the view `run` say which program runs now (`docs/daemon-api.md`, "The step in
  flight"); `step_in_flight` is a new optional member, so a client that validates a run row strictly against the
  schema of 0.9.3 must take the new schema. A revision of the runbook made while a run waits no longer ends it.
- **The daemon drains on SIGTERM or SIGINT** instead of ending the runs it holds: it refuses a submit with `503`,
  lets every live run go on to its own outcome and exits 0 when none is live (`docs/daemon-api.md`, "Stopping the
  daemon"). A second signal or `--drain-seconds` ends it at once, with exit 75 when a run was live.
- **A refused action ends the run by name,** `refused`, exit 12, cause `program_error`, where it ended `stuck` with
  no reason; a `--recorded` re-drive no longer books the cost of the recording as money it spent; a spend cap with
  nothing left starts nothing that may spend.
- **The Products tab of the inspector lists what the run wrote,** by the step that wrote it, newest first, with the
  seeded files as one line "Inputs" (`ui/README.md`). The inspector says when the list of file changes it keeps is
  not the whole record, and bounds that list in bytes.
- **The files of a run directory are written and read without following a link.** `runbook run`, its watcher and the
  inspector make, open and read the files of a run directory as new or regular files, through descriptors they hold,
  within a bound (`docs/loom-run-directory.md`; the entries of `CHANGELOG.md` under Fixed say each).
- **A money cap is optional in `driver/` too** (`sdc-experiment`, `sdc-replay`, `sdc-node`, `sdc-free-agent`): none
  named means no limit and no refusal, a named value that cannot be read is refused by name.
- **For contributors:** `task check` runs the steps that need no result of a test step beside the test steps; the test
  step of `runbook/` runs the nextest profile `forge` when `CI` is set and its dependencies build at `opt-level = 1`;
  the cases that built large trees take their bound as a parameter.

### How to try it

There is no binary to download: build from the checkout. Each command below exists in this tree.

1. `scripts/install.sh --prefix <absolute dir>` installs into a directory you made (it builds in release mode,
   which takes minutes; `README.md`, "Try it").
2. In an empty directory, `runbook init` writes a starter `runbook.toml`, and `runbook config` prints each value of
   `runbook run` with its origin. `runbook list` names the runbooks it finds.
3. `runbook serve --help` lists the options of the daemon, among them `--default-confinement`, `--autonomy`,
   `--decider` and the three caps `--runtime loom` requires.
4. Check the release: `task release:check VERSION=0.10.0`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **No binary asset.** A user builds from a checkout with `scripts/install.sh --prefix <dir>`; the script is the
  source of an asset that does not exist yet (`docs/releasing.md`, "The binary").
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.9.3. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending` (`docs/cycles-suite.md`); no run has told a
  `rework_limit` of 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom at the pin; no other form is claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader
  is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` still names the child binary of Loom `70b0e6e0`** and compares a
  library of `d8944d49` with it (`docs/loom-run.md`).
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/run_loop.rs`). A run of the daemon's stub
  runtime, in which nothing is executed, and a run directory an older `runbook` wrote have none, and the inspector
  shows them as it showed them before.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends; the only file that grows while a step runs is under
  `work/.sdc/llm/`, a dot-directory the inspector never serves (`docs/loom-run-directory.md`).
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **A run with no money cap named is not limited in money.** `runbook run` and `sdc-experiment` start a run with
  no `--cap-micro-usd` and no `--max-llm-calls`; the daemon with `--runtime loom` is the exception, it requires its
  caps and their ceilings (`docs/loom-run.md`, `docs/daemon-api.md`). A call of unknown cost in a run that names no
  spend cap books nothing. In a run opened with a model node the printed command of a handoff runs as printed under
  a named cap too, so several steps spend from one reservation before the cap is looked at again; the story
  `handoff-under-a-named-cap-runs-one-step-at-a-time` (proposed) is the bound for it.
- **A daemon run is read on disk.** Its products are under the daemon's state directory (`runs/<run_id>/` and
  `workspaces/<run_id>/`, `docs/daemon-api.md`): no tool or route serves them yet, and served by the daemon the
  Products tab says "the daemon serves no files of a run yet".
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count
  read from the tree or from a command named above. The times in `CHANGELOG.md` for the test steps and for the
  inspector's idle work were measured on the build host or the forge and are in no record of `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
