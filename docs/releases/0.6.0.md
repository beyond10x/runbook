# Runbook 0.6.0

A minor release of 0.5.0, the day after. `runbook run` routes decisions by autonomy level from a
table it reads once before the first action, `runbook run --recorded <source>` re-drives a case tree
from a recording, `runbook canon` runs the linked Canon library, and the run inspector is read-only.
A source release at tag `0.6.0`; nothing is published to crates.io and no interface is stable.
`CHANGELOG.md` lists the changes with their sources. Read `docs/releases/0.5.0.md` for the release
this one follows.

### What this release holds

- **Decisions are routed by autonomy level.** `tools/autonomy-levels.json` (`sdc.autonomy-levels/1`,
  the table of `docs/autonomy-levels.md` § 2.2; a test compares the two) names the holder of each
  class at each level. At A1 to A4 the decider answers only a class the table gives to `decider`;
  every other holder, an unknown class and a missing or inconsistent table stop the run for a person
  with no model call. At A5 the close through `operating` is taken by `rule:autopilot` with no decider
  call, and `escalate: final` applies at A5 only. A rejection of an action that declares no `rejected`
  result stops the run `stopped: rejected` (exit 10, cause `rejected_without_rework_path`) instead of
  `error`. The record of a close names its decider (`rule:autopilot`, `decider:model`), never a person
  (`docs/loom-run-decisions.md`).
- **The routing is read once.** The runner reads the table and the classes of decisions right after
  the copy of the bindings is made and before the first action (`Decider::pin_routing`), and routes
  every decision of the run from that read. A rewrite of the run's copy during the run changes no
  routing.
- **`runbook run --recorded <source>` re-drives a case tree.** Every model and decider call is
  answered from a recording or a run directory by `sdc-replay`. `--on-divergence stop|nearest|live`,
  `--live-adapter`, `--live-cap`, `--inject`, `--set`, `--take-recorded` and `--source-tree` need
  `--recorded` (exit 64 without it). A run that leaves the recording ends `stopped: recording
  diverged` with exit 11 (cause `recording_diverged`); the live cap counts a call from its start and
  fails closed. The old exit 4 `writer_spent` is `stuck` (exit 3) (`docs/loom-run.md`, "A recorded
  run"). `sdc-experiment` passes `flags.recorded` and the settings that go with it to `runbook run`.
- **Canon is linked.** `runbook canon validate|compile|check|simulate|evaluate` runs the Canon
  library the crate links (`b10x-canon`, tag `0.11.0`) with the arguments, output and exit statuses
  of the `canon` binary of that release. `scripts/evaluate-cases.sh`, `scripts/check-protocols.sh`,
  `scripts/limitations.sh`, the skills `harden` and `record` and `.github/workflows/protocols.yml`
  call it; `driver/canon-pin.json` is gone and the pin is the `b10x-canon` entry of
  `runbook/Cargo.lock`. `runbook doctor` needs no `canon` binary: its `canon` row is the linked
  Canon and is `ok` on every host.
- **The inspector is read-only.** The Approve, Answer, Change and Continue acts, `POST /api/act`, and
  the options `--write`, `--write-only` and `--principal` are gone: an unknown option exits 2 and
  any request that is not a GET or a HEAD answers 405. A decision is answered through the daemon
  (`runbook serve --ui`, `runbook decide`). The inspector reads a file of a run only when its real
  path lies under the run directory (`ui/runfiles.mjs`), and refuses with 421 a request that is not
  addressed to its own loopback host. It shows a run of `runbook run` that ended well as a good end,
  applies a view file to such a run, and draws its graph from the protocol and the run's bindings
  copy (`ui/README.md`).
- **`scope.answer` is a person step with a program.** The engine runs
  `tools/sdc-tool.sh scope-answer` at the approval, through the runner of the run's `--confinement`,
  with the approving principal. Loom `70b0e6e0` is linked in place of `5b3142c7`; Canon stays at
  0.11.0 and Substrate moves from 0.21.0 to 0.24.0.
- **The effort per node class reaches a model node.** `sdc-node --effort <level>` takes a level of
  `bindings/tools/node-classes.json`, and the settings key `efforts.<role>.effort` (roles `writer`,
  `implement`, `review`, `other`) is written by the bindings copy into the model nodes of the role.
  A level outside the set is refused by name before the run directory is made.
- **The decision contract (`ess/domains/decision.yaml`) refuses more.** `Decide` and a verified
  `Recommend` refuse a letter the request does not offer (`OptionNotOffered`); `Escalate` refuses a
  principal who is not in the request's `eligible` list (`NotEligible`); `Request` refuses options
  that repeat a letter (`DuplicateOptionLetter`); `RecordProduced` refuses an empty record id
  (`EmptyRecordId`) before it looks for the request. The ESS pins move from 0.97.3 to 0.97.4; the
  committed suites are byte-identical.
- **Record.** `experiments/parity-loom-strong-4.yaml`: three runs of the to-do idea through
  `runbook run` in process. It is descriptive; see Limits.

`runbook --version` prints 0.6.0.

### Breaking

- The inspector's acts are gone: `POST /api/act` and the options `--write`, `--write-only` and
  `--principal` of `ui/server.mjs` no longer exist, and the view file no longer has the members
  `tool_owners`, `decisions.scope_answer.check`, `refused_answerers`, `decisions.context` and
  `decisions.continue` (a view that has one is refused).
- A run without a readable routing table stops every decision for a person, at A5 too (exit 8). The
  table is read before the first action at every level.
- The decision contract refuses four inputs it took before: a letter nobody offered, an escalation
  to a principal who is not eligible, a repeated option letter, and an empty record id.

### How to try it

Build with `cargo build --bins` in `driver/` and `cargo build --bin runbook` in `runbook/`. Each
`--help` below was run on this tree.

1. `runbook --version` prints 0.6.0; `runbook doctor` lists the linked Canon and needs no `canon`
   binary.
2. `runbook canon --help`, then `runbook canon validate --path protocol/sdc-bugfix.protocol.yaml`.
3. `runbook run --help` prints the options, `--recorded`, `--on-divergence` and `--live-cap` among
   them. `docs/loom-run.md` ("A recorded run") says how a re-drive is made.
4. `--effort <level>` is in the usage comment of `driver/src/bin/sdc-node.rs`; the levels are those of
   `bindings/tools/node-classes.json`.
5. Read how a decision is routed in `docs/loom-run-decisions.md`; the table is
   `tools/autonomy-levels.json`.
6. Check the release: `task release:check VERSION=0.6.0`, and the experiment records with
   `sdc-experiment check --all`.

- The bindings hold 14 model nodes, all started through `sdc-node`.
- `cycles/suite.yaml` lists 130 cycles. `cycles/tree-suite.yaml` holds 54 of them: 37 converted and 17
  pending, which leaves 76 not converted (`docs/cycles-suite.md`, "Totals and time").
- 16 tests are `#[ignore]`d in the default test step; each names the slow lane that runs it
  (`task test:replay` for nine of them). The six tests that were ignored in 0.5.0 for a difference
  between the runner and the old driver are rewritten and run.
- `runbook canon` is byte-equal to the `canon` binary of 0.11.0 on the 9 protocols and the 52
  evaluations of `cases/`, apart from the usage text of a command line it refuses (`CHANGELOG.md`).
- `experiments/parity-loom-strong-4.yaml`: 3 runs, 0 delivered, 0 clean passes; the three stopped with
  cause `stuck` after 16, 7 and 19 calls; the spend ledger holds 3.953 USD of its 14.54 USD stop line.
- The tests of this code ran green on the forge for the merge commits `ad181f9` and `c68ca14`, the
  base of this release. No count and no time of a test step is claimed here: the machine that
  prepared this note ran none (its load average was above 140).

### Limits

- **The evaluation did not deliver.** The three runs of `experiments/parity-loom-strong-4.yaml` on this
  code delivered 0 of 3; all stopped `stuck`. The record's facts give two causes. A model node that is
  not called (a finding waits for a person, or the decisions it would follow are the defaults) exits
  0 and counts against `budget.max_runs`: run 1 reached `RunsSpent` at `spec.author` after one model
  call in four runs, and run 3 at `change.implement` (the draft `story:bindings-state-their-exits`
  holds the fix; it is not built). Run 2 stopped after `requirements.check` exited 5 and the handoff
  check of `amend.upstream` exited 1; the record infers, and does not prove, that this is Loom
  `70b0e6e0` dating a performed action by the next `evaluated` line (`ActionFinished.revisions` is
  written empty, so selection rejects the action as not useful). The record decides nothing: its
  verdict is `descriptive`, and no parity verdict between the old driver and Loom exists.
- **No statement about speed, quality or cost goes beyond `experiments/`.** The release claims no
  measured change over 0.5.0 or over the old driver; a figure in these notes is one that a record of
  `experiments/` carries or a count read from the tree.
- **The old driver is still in the tree.** `sdc-drive`, `scripts/run-trial.sh`,
  `bindings/tools/llm-node.sh` and `bindings/tools/decider.sh` are there; `runbook run` starts none of
  them and `sdc-experiment run` starts a run only with `runbook run`. Their deletion is not in this
  release.
- **The cycles are not all converted.** Of the 130 cycle entries 37 are converted to the tree suite and
  17 are pending; 76 are not converted. The whole file is a slow lane, `task test:cycles-loom`; neither
  it nor `scripts/run-finding-cycles.sh` was run on this tree for this note. Nine of the ten replay
  entries are Rust tests that run in the slow lane `task test:replay`, which was not run for this
  note either (`docs/cycles-suite.md`).
- **`sdc-experiment` does not carry an effort.** It refuses `efforts.*` in a `loom` variant: the record
  format does not carry an effort to the runner yet, so the class defaults apply to a run it starts.
  `sdc-node --effort` and the settings file of `runbook run` do carry one.
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime unless `--runtime loom`
  is given (`runbook/src/serve.rs`, `docs/engine.md`). The Loom runtime is run through the slow lane
  `task test:engine-real`, not by the gate.
- **`--confinement local` is unconfined.** `local` is "unconfined and declared insecure"
  (`docs/loom-run.md`): a bound program can write the whole run directory, including the copy of the
  routing table (the runner reads it once, so a rewrite changes no routing), the decider's
  instruction files and adapter, and the replay plan and call log. Under `--confinement substrate`
  the run directory is out of a bound program's reach (`docs/loom-run-decisions.md`).
- The rule approver (`SDC_RULE_APPROVALS`, claims of the position), the rework cap of the old driver and
  the end by rule `withhold` are not in the runner: Loom's output holds no claim values and Loom has no
  such steps (`docs/loom-run-decisions.md`).
- `task check:ess-suite:slow`, the byte comparison of a new synthesis with the committed suite, and
  `task docs:test` were not run for this release; the fast digest check is part of
  `task check:ess-generated`.
