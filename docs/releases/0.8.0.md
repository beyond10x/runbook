# Runbook 0.8.0

A minor release of 0.7.0, the same day. The run inspector has a Products tab: for the node a user picked it
lists the files the step left under `work/` and shows one as text. Loom `c9b4c177` is linked: a model node
that was not called no longer counts against `budget.max_runs`. The bindings state their exits
(`exits.error`, `exits.not_called`) and `scripts/check-bindings.sh` checks them. `runbook test` takes
`--cycle-timeout` and `--list`. A source release at tag `0.8.0`; nothing is published to crates.io, there is
no binary asset and no interface is stable. `CHANGELOG.md` lists the changes with their sources. Read
`docs/releases/0.7.0.md` for the release this one follows.

### What this release holds

- **The inspector has a Products tab** (`ui/`, story `inspector-shows-step-products`). For the node a user
  picked it lists the evidence records of the case, the actions (exit code, the tail of the output) and the
  files under `work/` of the run and of each case, and opens one: a `.txt` step file with its `result:` line,
  JSON indented, YAML as written, Markdown rendered by `ui/web/markdown.js` (it builds elements from text and
  never assigns markup). A file over 1 MiB is shown cut at 1 MiB with its full byte count; a file that is not
  UTF-8 text is shown by its size and type only. A field the run did not record says "not recorded by this
  run": `runbook run` records no start, end or duration per action, so the tab shows the span of the step
  from `observed.jsonl`. The view file has a new member `product` (a path inside the run directory;
  `runbook check` refuses a value that is not a string, is empty, is absolute, leaves the run or has a dot
  component), and the product line under the header says which rule named the product. The inspector only
  reads: `/api/products`, `/api/file` and `/api/output` serve regular files under a `work/` directory of the
  run through the run-path check on the open file, and nothing else (`settings.json`, `store/` and
  `llm-calls.jsonl` are not served). `ui/README.md` ("What a step produced") says which files are listed
  and which are not, and `docs/daemon-api.md` says what the daemon's page shows.
- **Loom `c9b4c177` is linked** (it replaces `db2726ff`; version 0.59.0, branch `wave/2026-11-21-w7` of the
  engine, in no tag; `c9b4c1777c646afdfae843dae691da36859f56ee`). A writer whose program ends "not called"
  (`exits.not_called`) leaves the due set until the case is evaluated again for a reason other than its own
  moves: it is started once per evaluation, no run of it is counted against `budget.max_runs`, and the run
  goes on to the next useful action or to the handoff check. In `runbook/Cargo.lock` only the 14 Loom
  packages move.
- **The bindings state their exits.** Each of the 50 program bindings of `bindings/*.yaml` has `exits.error`
  (`[75, 126, 127]`; `[69, 70, 75, 126, 127]` on the five that wait for the build pool), and each of the 14
  model nodes `exits.not_called: [79]` (`docs/loom-bindings.md`, "The exit lists"). `sdc-node` exits 79 where
  it prints "not called" and writes no evidence (`questions.write` with an interview, findings that wait for
  a person); a tool that cannot run ends the run `ProgramError` and no run of it is counted. The lines of
  D36, D37 and the pool-wait exits leave `bindings/PENDING.md`.
- **`scripts/check-bindings.sh` checks the exits.** It refuses by name an `exits` class that Loom does not
  read (it reads `error` and `not_called`), a class that is not a list of exit codes, an `exits` that is not
  a mapping, a code in both classes or in a result table, and a binding with no list.
  `check-bindings.sh --exits <root>` runs that check alone over `<root>/bindings/*.yaml`
  (`driver/tests/check_bindings_exits.rs` has one case per refusal).
- **`runbook test --cycle-timeout <seconds>` and `--list`.** `--cycle-timeout` is 1 to 60 (default 60,
  Loom's `cycle_timeout`): a cycle past it has its running program killed and ends `CycleTimedOut`, naming
  its step; a whole number outside the range is exit 2, a word exit 64. `--list` prints one line per cycle
  (`<name>`, `<name>: pending`, `<name>: pending, waits for story:<id> (<kind>)`), runs nothing and needs no
  `--confinement`. Both are in `--help`.
- **The driver finds the workspace where Loom started the program.** `sdc_tools::reply::records::case_work`
  is the one place that decides it: under `LOOM_CASE` the current directory, without it `<case dir>/work`
  (`driver/tests/workspace_layout.rs`, `workspace_empty_loom_case.rs`). Before, the rejections of
  `change.review` were counted as none at the new layout of Loom's suite.
- **New no-model tests.** The state of run 1 of record `parity-loom-strong-4` (`runbook/tests/test_suite/
  notcalled.rs`: a writer not called while a finding waits for a person is started once and the run stops
  `AwaitingPerson`, red at `db2726ff` and green at `c9b4c177`) and its neighbours
  (`notcalled_neighbours.rs`: an exit 79 the binding does not list is a counted run, a program not called on
  every evaluation, two writers not called at once, a writer that writes and then exits 79).
- **Three fixes of the inspector for a run of `runbook run`.** It no longer says "Nothing" about what changed
  in a run with no `fs/changes.jsonl` (it says the changes were not recorded and names `--watch`), it takes
  the protocol revision of a case from the `opened` event, and it no longer shows a claim count of 0/0 for a
  run that records none (`ui/test/loom-run-record.spec.mjs`).
- **The test step of the runbook crate reads no `ess` of the host.** The `exit_classes` test brings its own
  stand-in `ess`, `yq` and `jq`, and `task test:runbook` puts `scripts/host-tool-traps` first on `PATH`, so
  the step no longer depends on which tools the machine has (it was red on a runner with no `ess`).

`runbook --version` prints 0.8.0.

### Breaking

- **`sdc-node` exits 79 where it exited 0.** At "not called" (`questions.write` with an interview, findings
  that wait for a person) the program printed its reason and exited 0; it exits 79. A bindings file of a user's own that starts `sdc-node` without `exits.not_called: [79]` has no
  class for 79: Loom ships no default list, so the exit goes to the action's `from: exit` result table (a
  code the table does not name, with no `*` key, is Loom's refusal `ResultNotInTable`, `docs/loom-run.md`)
  and is a counted run against `budget.max_runs` (`runbook/tests/test_suite/notcalled_neighbours.rs`, the
  first case, with a `*` key in the table). A derived tree that is only renewed
  still exits 0.
- **A bindings file with no `exits` has no exit class.** Loom reads `exits.error` and `exits.not_called` and
  has no default list (`docs/loom-bindings.md`). Without them 75, 126 and 127 do not end a run `ProgramError`:
  they are read through the result table like any other code. `scripts/check-bindings.sh` reads only the
  files of this repository's `bindings/` (and `bindings/*.yaml` under the root given to `--exits`), and it
  fails on a program binding there that has no list (`exits.error is [], want [75, 126, 127]`); it is not a
  check of a file elsewhere.
- **The scratch layout of a suite cycle.** A cycle works in `<scratch>/work/<n>` and keeps its tree in
  `<scratch>/store/<n>` (it was `<scratch>/<n>/work` and `<scratch>/<n>/store`; Loom `c9b4c177`). A
  bound program starts in the workspace root with `PATH`, `LOOM_CASE`, `LOOM_TIMEOUT_SECONDS`,
  `LOOM_CASE_NAME` and `LOOM_PARENT_CASE_NAME`, and is told no case directory and no store. A script that
  reads those directories changes.
- **`runbook test` prints Loom's `slowest:` line** in place of the `ten slowest:` block. `--workers` above 16
  under `--confinement substrate` is refused with `SubstrateWorkersUnserved` (it was above 1); `substrate`
  itself is still refused by `runbook test`.
- **`sdc-tool.sh` keeps no log record of a tree that does not exist yet.** The first `spec.gate` of an epic
  (it runs before the spec does) fails as before and no longer ends the run `ProgramError` with exit 126.

### How to try it

There is no binary to download: build from the checkout (`README.md`, "Try it"). Each `--help` below was run
on this tree.

1. Build: `cd driver && cargo build --locked --bins`, then `cd runbook && cargo build --locked --bin
   runbook`. `runbook --version` prints 0.8.0.
2. `runbook test --help` lists `--cycle-timeout` and `--list`. `runbook test cycles/tree-suite.yaml --list`
   prints one line per cycle and runs nothing.
3. The inspector: `cd ui && node server.mjs --port 7490 <run directory>/store` (`ui/README.md`, "Start"),
   open `http://127.0.0.1:7490/`, pick a run and a node, and open the Products tab.
4. `scripts/check-bindings.sh` checks the bindings, among them the exits; `scripts/check-bindings.sh --exits
   <root>` checks the exits alone. `runbook check` checks the text layout, the bindings, the instruction
   files, the views and `cycles/tree-suite.yaml`.
5. Check the release: `task release:check VERSION=0.8.0`, and the experiment records with
   `sdc-experiment check --all`.

### Numbers

- The bindings hold 50 program bindings with `exits.error` and 14 model nodes with `exits.not_called`
  (`grep -c` over `bindings/*.yaml`).
- `cycles/tree-suite.yaml` holds 55 cycles: 40 converted and 15 pending (40 and 14 in 0.7.0; the new one is
  `spec-person-wait`). `cycles/old-suite-names.txt` lists the 131 names (the 130 of the deleted suite and
  `spec-person-wait`); 39 entries are held by Rust tests and 37 are dropped (`docs/cycles-suite.md`,
  "Totals and time").
- 15 Rust tests are `#[ignore]`d in the default test step (as in 0.7.0).
- `scripts/check-bindings.sh` finds 36 routes (as in 0.7.0).
- No count and no time of a test step is claimed here: the machine that prepared this note did not run the
  test steps (its load average was 91 to 110, and a test step ends over its 120 s budget there); the forge
  runs them on the pull request.

### Limits

- **No evaluation run was made on this code.** The three runs of record
  `experiments/parity-loom-strong-4.yaml` ran on the code of 0.6.0 and delivered 0 of 3; all stopped
  `stuck`. Of the three causes the record showed, the not-called one is fixed by this pin and shown by a
  no-model test only (`runbook/tests/test_suite/notcalled.rs`); the cause of run 2 (an action dated by the
  next `evaluated` line) is what `db2726ff` of 0.7.0 changed, also shown by a no-model test only. A rejection
  still gives the writer no new allowance of runs: `decider-rework-spent` and `rework-fresh-allowance` failed
  on `RunsSpent` at `db2726ff` and are `pending`; at `c9b4c177` they ended on Loom's 60 s bound (60.6 s and
  61.2 s), so the failure is not observed again here (`docs/cycles-suite.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that the eight entries the layout change may touch were run at a one-minute
  load of 94 to 156: seven ended `CycleTimedOut` at the bound (`review-reject-once` 62 s,
  `review-minimal-input`, `review-invalid`, `review-spent`, `implement-request-review-rework`,
  `coverage-complete` and `implement-request-path-escape`, 60 to 62 s) and `review-invalid-named` ended as
  expected in 49 s. That no entry changed from expected to another state is not observed on that host; it
  needs one run of the suite at a load where a cycle ends inside the bound, and that run has not been made.
- **`spec-person-wait` and `cite-fault-sent-back` stay `pending`.** The writer loop is gone (the cycles
  stop `AwaitingPerson`, exit 3), and the person's decision is out of reach of the suite until a step can write a
  workspace file (no Loom story yet).
- **No statement about speed, quality or cost goes beyond `experiments/`.** The release claims no measured
  change over 0.7.0; a figure in these notes is one that a record of `experiments/` carries, a count read
  from the tree or a count of a command named above.
- **No binary asset.** A user builds from the checkout.
- **The inspector is read-only and has no route to the daemon.** It starts no program, takes no decision and
  sends no command to the daemon (`ui/README.md`). Served by the daemon (`runbook serve --ui`) the Products
  tab says "the daemon serves no files of a run yet" and lists nothing: the daemon's API has no view of the
  files, evidence records or output of a run (`docs/daemon-api.md`).
- **What the Products tab does not list or serve** (`ui/README.md`, "What a step produced"): a path with a
  component that starts with a dot (a tool's cache or login), a link that leaves the run, a file with more
  than one link, a `work/` that is a link, and anything outside a `work/` directory. A file over 1 MiB is shown
  cut, and a file that is not UTF-8 text by size and type only. The listing stops at 500 files, 2000
  directories or 20000 entries, and does not enter a directory deeper than 6 levels; the page says what it cut.
- **The runner's records are short.** The projected events drop Loom's `blob_digest`, so the page reads Loom's run log
  of the case, and the runner records no start, end or duration per action (`ui/README.md`).
- **The old driver's records keep its names.** Records of past runs (`cases/**/evidence`, `experiments/`,
  the recorded run of `ui/test/recorded/`) keep the producer id `sdc-drive`, and the record
  `parity-loom-strong-4` names files that are deleted now.
- **The cycles are not all converted.** Of the 131 names, 40 are converted, 15 are pending, 39 are held by Rust
  tests and 37 are dropped. The whole file is a slow lane, `task test:cycles-loom`; it was not run on this tree
  for this note, and `docs/cycles-suite.md` says that cycles run at a one-minute load of 100 to 177 ended on
  Loom's 60 s bound.
- **`sdc-experiment` does not carry an effort.** It refuses `efforts.*` in a `loom` variant: the record format
  does not carry an effort to the runner yet, so the class defaults apply to a run it starts. `sdc-node
  --effort` and the settings file of `runbook run` do carry one.
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`runbook/src/serve.rs`, `docs/engine.md`); the daemon's default
  confinement floor is `linux` and `local` must be asked for by name (`docs/daemon-api.md`).
- **`--confinement local` is unconfined.** `local` is "unconfined and declared insecure"
  (`docs/loom-run.md`): a bound program can write the whole run directory. Under `--confinement substrate`
  the run directory is out of a bound program's reach (`docs/loom-run-decisions.md`).
- **The child binary of `runbook run --loom` is still the one of `70b0e6e0`.** The library links `c9b4c177`;
  the slow lane `task test:loom-in-process` compares it with that child (`docs/loom-run.md`).
- The rule approver (`SDC_RULE_APPROVALS`), the rework cap of the old driver and the end by rule `withhold` are
  not in the runner (`docs/loom-run-decisions.md`).
- `task check:ess-suite:slow`, the byte comparison of a new synthesis with the committed suite, and
  `task docs:test` were not run for this release; the fast digest check is part of
  `task check:ess-generated`.
