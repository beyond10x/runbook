# Runbook 0.15.0

A minor release of 0.14.0. Three changes are marked breaking: a context root of `runbook serve` that does not exist is
created with mode 0700 and an existing one with a group or other write bit stops the start; the copy of a run's
context leaves out `.git` and excluded paths and is bounded; a managed route that declares `price_per_hour_micro_usd`
counts its pod's measured time against its daily wake cap. A delegation can change a repository the operator lists on
its own branch, a first slice at `--confinement local` only. A route of any kind takes a daily spend or call cap, and
the view `routes` answers each route's figures of the day. A wake is booked only when the gateway took it, and the
agent node of a delegation gets no more turns than its run has model calls left. The aep pin is aep 0.81.0 with static
musl archives. A source release at tag `0.15.0`; nothing is published to crates.io and no interface is stable.
`CHANGELOG.md` lists the changes with their sources. Read `docs/releases/0.14.0.md` for the release this one follows.

### Breaking changes

- **A missing context root is created; a root others can write stops the start.** `runbook serve` creates a context
  root (of `context_roots` in `runbook.toml` or of `--context-root`) that does not exist, with mode 0700 and its
  missing parents, where it stopped the start before. An existing root is never changed: one with a group or other
  write bit now stops the start naming its mode, one wider than 0700 without them is named in the start log. A root
  that is no directory, or that cannot be read or created, stops the start with exit 2 where it was exit 1. The
  remedy: take the group and other write bits off a shared root (`chmod go-w <root>`), check a root's path before the
  start since a mistyped one is now created, and read exit 2 for a refused root (`docs/daemon-api.md`, "Context
  roots"). `Daemon::start` of the library still refuses a missing root.
- **The copy of a run's context leaves out `.git` and excluded paths, within a bound.** The copy of `context_path` of
  a submit or `workspace` of a delegation leaves out every entry named `.git` and the entries of `[delegation]
  copy_exclude` (default `target/` and `node_modules/`, a name at any depth or a relative path from the context root),
  and reads at most `copy_max_entries` entries (default 50,000) and `copy_max_bytes` bytes (default 256 MiB). It copied
  the tree whole before. A context over a bound fails the run's start `context-over-bound: ...` and nothing of it is
  copied. The remedy: a run that needs `target/` or `node_modules/` gets a daemon whose `copy_exclude` names other
  entries (a list replaces the default); a context over a bound gets `workspace_exclude` on its submit or delegation,
  or a daemon with a larger `copy_max_entries` or `copy_max_bytes`. A `.git` is never copied: a delegation that must
  change a repository names it with `repository` (below) (`docs/daemon-api.md`, "The copy of a context").
- **A managed route with a pod price counts the pod's time against its daily cap.** A managed route that declares the
  new key `price_per_hour_micro_usd` books the time its pod ran for its runs, split equally over the runs that used it,
  against `wake_daily_cap_micro_usd` beside its wakes, so the same cap admits fewer wakes. A route without the key
  books as before. The remedy: raise `wake_daily_cap_micro_usd` by the pod time a day is to hold, or leave the key out
  (`docs/daemon-api.md`, "The pod's time of a managed route"; `docs/model-routes.md`, section 5).

### What this release holds

- **A delegation changes a repository on its own branch, first slice** (`docs/daemon-api.md`, "A delegation that
  changes a repository"; `docs/model-routes.md`, section 7). The operator lists repositories in `runbook.toml`
  (`[repositories.<name>]`, none by default); the command `delegate` and `runbook delegate` take `repository`, the
  name of an entry, never a path. The run takes the path `change` and the runbook `delegation-change`: the daemon makes
  the run's worktree with the host's `worktree` command, the agent node works in it, and on `delivered` the daemon
  commits under the entry's identity and pushes the new ref `refs/heads/runbook/<run-id>`, never forced and never with
  a path of `deny_paths` (by default `.github/`, `.gitlab-ci.yml`, `.gitmodules`). The view `delegation-result` names
  the branch and the commit, or why the hand-back was refused.
- **A route of any kind takes a daily cap** (`docs/model-routes.md`, section 5; `docs/daemon-api.md`, "The day's
  figures of a route"). `daily_cap_micro_usd` (on a route that declares a price) and `daily_max_llm_calls` in
  `[routes.<name>]`; past either the relay answers `429 cap-reached` naming the key, sends nothing, and the run ends as
  a run at a cap. Two runs on one route share its figures, and a daemon started again rebuilds them from its ledgers.
- **The view `routes` answers each route's figures of the day** (`docs/daemon-api.md`, "The day's figures of a
  route"). Every row (and the catalog and the MCP tool `list_routes`) answers `daily_booked_micro_usd` and
  `daily_llm_calls`; a managed route also the figures its wake cap counts (`wake_booked_micro_usd`,
  `wake_cap_micro_usd`, `wake_cost_micro_usd`, `wake_needed` and the rest).
- **A wake is booked only when the gateway took it** (`docs/daemon-api.md`, "The wake of a managed route"). A wake
  answered `4xx`, `5xx` or not within 5 s books nothing; one answered `5xx` other than `spend-ceiling`, or not at all,
  is sent again after 30 s while the gateway gives the model as `stopped` and the run waits for its route.
- **A priced answer with no usage books its reservation** with `cost_known: false`, where it booked 0
  (`docs/model-routes.md`, section 5).
- **`runbook.toml` names the daemon's context roots** (`context_roots`, at most 64), which `--context-root` adds to
  (`docs/daemon-api.md`, "Context roots"). A submit and a delegation take `workspace_exclude` (at most 64 entries).
- **The agent node of a delegation gets no more turns than its run has model calls left** (`docs/daemon-api.md`, "A
  delegation"). The daemon names `RUNBOOK_CALLS_LEFT`, and `sdc-node` takes the smaller of it and its `--max-turns`.
- **The aep pin is aep 0.81.0** (`driver/aep-pin.json`, commit `ff194ee2`; replaces 0.80.0), whose pin names
  `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, so the `sdc-conform aep-install` of a musl build
  installs the static aep. `task test:driver` runs that static aep on every Linux host, so a host with glibc older than
  2.39 runs the driver tests (`docs/forge-gate.md`).
- **The test steps cost less**: a `b10x-loom` call ends when its child exits and a daemon run when its steps are done,
  not at the next poll; the runbook and UI test steps wait for events instead of fixed times. The two race specs of the
  inspector's file reader swap with `renameat2`, not `mv --exchange`, which coreutils before 9.5 lacks.

### How to try it

1. Take an archive from the tag's GitHub Release once the release workflow has uploaded it: check it with
   `sha256sum --check runbook-0.15.0-<triple>.tar.gz.sha256`, unpack it, and put its `bin` on `PATH`
   (`README.md`, "Try it"). Or build from the checkout: `scripts/install.sh --prefix <absolute dir>` (release mode).
2. `runbook serve --principal agent:<id> --runtime loom` with a `runbook.toml` that declares a route with
   `daily_max_llm_calls`, then `runbook catalog`, `runbook delegate --route <route> <request-file>` and the view
   `routes` (`docs/daemon-api.md`, "A delegation", "The day's figures of a route").
3. Check the release: `task release:check VERSION=0.15.0`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **A delegation that changes a repository is a first slice.** It runs at `--confinement local` only, where there is
  no OS confinement and the agent node's write fence is its tool set and its working directory. Not built, each back
  to the operator first: the draft merge request and any forge client or forge token, the level `linux` and its Loom
  request, the hand-back as a step the bug-fix runbook shares, a base a delegation chooses, a fetch before the
  worktree is made, and the removal of a kept tree (`docs/daemon-api.md`, "A delegation that changes a repository").
- **No case forces two runs to take a route's last daily call at the same instant.** The case that two runs share a
  route's day (`two_runs_on_one_route_share_its_day_figure` in `runbook/tests/daemon/route_day_cap.rs`) sends their
  calls one after the other. The spend cap holds the booked figure, so the last call sent below it may take the day's
  figure above it by its own cost.
- **The run page does not show a route's figures of the day.** The view `routes` answers them; the page's Routes view
  shows the route, alias, kind, gateway, status, phase, wires and read time only (`ui/daemon/routes.js`).
- **A journal of this release may not replay in an older `runbook`.** A runbook older than 0.15.0 refuses to replay a
  journal that holds a `route.wake-answered` line, the daemon's own line for a wake answered after its run was closed
  (`docs/daemon-api.md`, "The wake of a managed route"), so a daemon's state directory with such a line is not opened
  by 0.14.0.
- **The ess pin names no musl archive.** `driver/ess-pin.json` (ess 0.98.0) lists gnu and darwin builds only, so
  `sdc-conform ess-install` of the musl archive installs the gnu ess, which needs glibc (`conformance::platform_for` in
  `driver/src/conformance.rs`). The aep pin names both musl archives since this release.
- **An agent node can still reach its run's call cap.** A call the CLI sends again after a failed answer, or a
  compaction, is counted by the relay and is no turn; a node that spends every call left ends the run `stopped: llm
  calls`, as before. The bound nodes of the SDC runbooks keep their fixed `--max-turns`.
- **A run on a route works at `--confinement local` only.** At `linux` a delegation on a route fails at once,
  `env: 'sdc-node': No such file or directory`, exit 127; the story `route-runs-at-linux-confinement` (draft) waits.
- **A tree left without a move by the step that reaches a cap shows the cap word**, not `Stuck`: telling it from a
  tree with a move left needs Loom to evaluate without a step (story `a-capped-runs-stuck-tree-shows-stuck`, draft;
  `docs/engine.md`).
- **A caller that half-closes its connection and still reads is not served.** The daemon's HTTP server drops its call
  as one that hung up (`docs/engine.md`, "A gateway").
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.14.0. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The relay is served on a loopback listener only.** On any other listener a run on a route does not start
  (`docs/daemon-api.md`, "The relay of a run's model calls").
- **Runbook does not read the gateway's `cost_usd`.** A call's cost is its route's declared prices, else the call is
  booked at its reservation with `cost_known: false` (`docs/model-routes.md`). A pod's price is the route's own
  `price_per_hour_micro_usd`: the gateway serves its `price_per_hour_usd` on no route a client reads.
- **A generated protocol of a delegation runs only the daemon's agent node.** The programs and child runbooks of the
  catalog are not built into it (`docs/model-routes.md`, section 9).
- **The default spec check tests that a reference is there, not that the spec says what the fix does.** It reads the
  whole description, so a code path under the spec directory (a test tree named `spec/`) counts; name another
  directory with `--spec-dir` (`docs/bugfix.md`).
- **The default description writer is a program and reads no feedback.** Sent back after a refusal it writes the same
  description unless its inputs changed; `sdc-check-routes` lists this as a `not-handed` finding of `handback.describe`,
  and a model writer bound in its place gets the refusal line (`docs/reject-routes.md`).
- **A gateway of `runbook run` works at `--confinement local` only.** Under `substrate` a bound program has no network,
  so the runner refuses a gateway there by the name `gateway`. `llm-adapter-metaharness.sh` cannot take one (it
  removes every `ANTHROPIC_*` variable and starts its own proxy) and ends with exit 127 when it is given one. With an
  `http://` address at a host that is not loopback the token travels in clear text; the choice is the user's
  (`docs/loom-run.md`).
- **The forge runs no UI specs.** At the forge's CPU count the UI step does not end inside the 120 s step budget, so a
  UI change is checked by the local gate only (`docs/forge-gate.md`; the `OUTSIDE` line of `check:ci-paths`).
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending` (`docs/cycles-suite.md`); no run has told a
  `rework_limit` of 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom when they were measured, at `d8944d49`; no measurement of them at a later pin is recorded, no other form is
  claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` compares a library of `b0a0dfda` with the child binary of Loom
  `70b0e6e0`** (its sha256 is pinned in `runbook/tests/loom_run/slow.rs`); no `b10x-loom` of `b0a0dfda` was built for
  it (`docs/loom-run.md`).
- **The recorded cycles run in `docs/cycles-suite.md` is at Loom `d8944d49`.** The file's last record of the whole
  suite is 55 cycles, `40 of 40 as expected, 15 pending`; the tree holds 56 cycles and the file has no record of a run
  of all of them.
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/in_flight.rs`). A run of the daemon and a run
  directory an older `runbook` wrote have none, and the inspector shows them as it showed them before.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends (`docs/loom-run-directory.md`). The daemon's run page shows the step
  in flight and its duration, not its output.
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **A run with no money cap named is not limited in money.** `runbook run` and `sdc-experiment` start a run with
  no `--cap-micro-usd` and no `--max-llm-calls`; the daemon with `--runtime loom` is the exception, it requires its
  caps and their ceilings (`docs/loom-run.md`, `docs/daemon-api.md`). A call of unknown cost in a `runbook run` that
  names no spend cap books nothing. In a run opened with a model node the printed command of a handoff runs as printed
  under a named cap too, so several steps spend from one reservation before the cap is looked at again; the story
  `handoff-under-a-named-cap-runs-one-step-at-a-time` (proposed) is the bound for it.
- **The daemon serves no evidence records and no action output of a run.** Its files under `work/` are served by the
  views `products` and `product`; the rest is read on disk under the daemon's state directory (`docs/daemon-api.md`).
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count
  read from the tree or from a command named above. The times in `CHANGELOG.md` and `docs/forge-gate.md` were
  measured on the build host or the forge and are in no record of `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
