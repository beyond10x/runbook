# Runbook 0.12.0

A minor release of 0.11.0. One change is marked breaking: a bug-fix run ends `fixed` only when a check program says
the description of its code merge request references a spec. The model programs of `runbook run`, and those of a
daemon run whose decider kind is `model`, reach a model through the address and token of a gateway, with no login. A
source release at tag `0.12.0`; nothing is published to crates.io, there is no binary asset and no interface is
stable. `CHANGELOG.md` lists the changes with their sources. Read `docs/releases/0.11.0.md` for the release this one
follows.

### Breaking changes

- **A bug-fix run ends `fixed` only when the check program says the description references a spec.** With this
  repository's bindings, a report or ticket that names no spec line, no spec merge request and does not say the spec
  says nothing ends stuck (runner exit 3) after the fix passed the gate, where it ended `fixed` before. The remedy: a
  runbook of another repository binds its own check after `--` of `handback-check`.

### What this release holds

- **A bug fix hands back only with a spec reference** (`docs/bugfix.md`, "Hand-back: the spec reference"). After
  `gate.run` the bug-fix runbook writes the description of the code merge request, `handback/mr-description.md`
  (action `handback.describe`, the program `sdc-bugfix handback-describe`: the fix summary and the ticket's text, no
  model call), and `handback.spec-check` runs a check program as `<check> <description file> <kind>` through
  `sdc-bugfix handback-check -- <check argv>`. One line `spec-first: allowed: ...` with exit 0 records
  `spec_reference` `ok`; `spec-first: refused: ...` with exit 77 records `refused`; 75, 126 and 127 stay program
  errors, and any other exit or a line that breaks the interface is exit 126, never a result. Neither table has a `*`
  row or a `timeout` row, so a check killed at its timeout records nothing, never `ok`. The claim `spec.referenced`
  holds only on `ok` and the outcome `fixed` requires it: a refused reference sends `handback.describe` back
  (`max_runs` 2) and never reaches `fixed`. The default check is `sdc-bugfix spec-check [--spec-dir <dir>]...
  [--spec-repo <url>]...`: a `change` passes with a merge request link of a spec repository or a path under a spec
  directory, a `defect` with a spec line or the words "spec says nothing". The ticket format `sdc.ticket/1` takes
  `change_kind: defect|change` (default `defect`). The cycle `bugfix-spec-refused` is new, and the Canon cases
  `handback-refused` and `handback-unchecked` of `cases/12-bugfix-red-first/` evaluate the state.
- **Model programs reach a gateway.** The settings of `runbook run` take a `[gateway]` table: a required `base_url`
  and at most one of `token` and `token_file`, never with a `login_file`. The runner writes one file (the address and
  the token, mode 0600) into its private directory (mode 0700), hands its path to every model node, the model decider
  and the conformance observation, and removes the directory when the run ends. `llm-adapter-claude-cli.sh` starts
  `claude` with `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` in the environment of that one start and no other
  `ANTHROPIC_*` or `CLAUDE_CODE_*` variable of the caller, with a config home that holds no login. The token is in no
  argv, no environment of a program Loom starts, no log line, no event and no file written into the run directory,
  and what `claude` prints passes a filter that replaces it. A `token_file` is opened without blocking and without
  following a link in its last component; a FIFO, a socket, a device and a directory are refused by the member's name.
  A `runbook.toml` can carry `[gateway]` (`base_url`, `token_file`); `gateway.token` there is refused by name
  (`docs/loom-run-settings.md`, "`[gateway]`"; `docs/loom-run.md`, "The gateway").
- **Runs started through the daemon take a gateway.** The daemon's operator names it in the `[gateway]` table of the
  `runbook.toml` the daemon reads; a daemon run whose decider kind is `model` gets it the way `runbook run` gives it,
  and a run of kind `rule` or with no kind starts no model program and writes no gateway file. The token file is read
  once when the daemon starts; a token file that cannot be read, and `[deciders.model]` with the adapter `metaharness`
  (its default), stop the daemon at start (exit 2) by the member's name. A submit that names `gateway`, `base_url`,
  `token`, `token_file` or `gateway.<member>` is refused (400) by that name and never with its value
  (`docs/engine.md`, "A gateway"; `docs/daemon-api.md`).
- **`sdc-experiment run` writes the gateway** (`base_url`, `token_file`) into the settings file of a `loom` run whose
  record names `gateway.base_url` and `gateway.token_file`; a record that names `gateway.token`, a relative token file,
  a gateway beside a login file or beside an adapter that cannot take it, and a `free-agent` variant that names a
  gateway, are refused by name (`docs/workflow-metrics.md`).
- **The forge runs the driver tests.** `.github/workflows/pages.yml` installs the pinned ess and the pinned aep 0.80.0
  (`driver/aep-pin.json`, `sdc-conform aep-install`, both digests checked) and runs `task test:driver` for a code
  change with the nextest profile `forge` (4 test threads); `task test:driver` puts the pinned aep ahead of a trap
  `aep` (`scripts/host-tool-traps/aep`, exit 127) on the `PATH` of the tests, here as on the forge.
  `task check:ci-paths` fails when a test step of `task check` has neither a forge step nor a reason it is left out
  (`docs/forge-gate.md`).
- **The UI test step costs less.** The UI tests run with `prefers-reduced-motion`, under which the page runs no
  animation and no transition and draws no blur behind a dialog or the drawer, and the run files are read without a
  real path per absent name. The ux loop keeps every effect.
- **`claude` and what it starts hold no descriptor above 2 that the caller of the claude-cli adapter left open without
  close-on-exec** (`bindings/tools/llm-adapter-claude-cli.sh`), and the descriptor cases start the adapter with such
  pipes open, so the local gate sees what the forge saw.

### How to try it

There is no binary to download: build from the checkout. Each command below exists in this tree.

1. `scripts/install.sh --prefix <absolute dir>` installs into a directory you made (it builds in release mode,
   which takes minutes; `README.md`, "Try it").
2. `runbook check` checks the runbooks and their bindings. The bug-fix runbook, `bindings/sdc-bugfix.yaml`, binds
   `handback.spec-check` with the default check `sdc-bugfix spec-check`.
3. Check the release: `task release:check VERSION=0.12.0`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **No binary asset.** A user builds from a checkout with `scripts/install.sh --prefix <dir>`; the script is the
  source of an asset that does not exist yet (`docs/releasing.md`, "The binary").
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.11.0. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The default spec check tests that a reference is there, not that the spec says what the fix does.** It reads the
  whole description, so a code path under the spec directory (a test tree named `spec/`) counts; name another
  directory with `--spec-dir` (`docs/bugfix.md`).
- **The default description writer is a program and reads no feedback.** Sent back after a refusal it writes the same
  description unless its inputs changed; `sdc-check-routes` lists this as a `not-handed` finding of `handback.describe`,
  and a model writer bound in its place gets the refusal line (`docs/reject-routes.md`).
- **A gateway works at `--confinement local` only.** Under `substrate` a bound program has no network, so the runner
  refuses a gateway there by the name `gateway`. `llm-adapter-metaharness.sh` cannot take one (it removes every
  `ANTHROPIC_*` variable and starts its own proxy) and ends with exit 127 when it is given one. With an `http://`
  address at a host that is not loopback the token travels in clear text; the choice is the user's
  (`docs/loom-run.md`).
- **The forge runs no UI specs.** On 2 CPUs the UI step does not end inside the 120 s step budget (550 to 587 of 611
  tests were done when the bound ended it, measured on the build node), so a UI change is checked by the local gate
  only until the test-budget defect of `test:ui` is fixed (`docs/forge-gate.md`).
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending` (`docs/cycles-suite.md`); no run has told a
  `rework_limit` of 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom when they were measured, at `d8944d49`; no measurement of them at `ed644a4d` is recorded, no other form is
  claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` compares a library of `ed644a4d` with the child binary of Loom
  `70b0e6e0`** (its sha256 is pinned in `runbook/tests/loom_run/slow.rs`); no `b10x-loom` of `ed644a4d` was built for
  it (`docs/loom-run.md`).
- **The recorded cycles run in `docs/cycles-suite.md` is at Loom `d8944d49`.** The file's last record of the whole
  suite is 55 cycles, `40 of 40 as expected, 15 pending`; the tree holds 56 cycles and the file has no record of a run
  of all of them.
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/run_loop.rs`). A run of the daemon's stub
  runtime, in which nothing is executed, and a run directory an older `runbook` wrote have none, and the inspector
  shows them as it showed them before.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends; the only file that grows while a step runs is under
  `work/.sdc/llm/`, a dot-directory the inspector never serves (`docs/loom-run-directory.md`).
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **A run with no money cap named is not limited in money.** `runbook run` and `sdc-experiment` start a run with
  no `--cap-micro-usd` and no `--max-llm-calls`; the daemon with `--runtime loom` is the exception, it requires its
  caps and their ceilings (`docs/loom-run.md`, `docs/daemon-api.md`). A call of unknown cost in a run that names no
  spend cap books nothing. In a run opened with a model node the printed command of a handoff runs as printed under
  a named cap too, so several steps spend from one reservation before the cap is looked at again; the story
  `handoff-under-a-named-cap-runs-one-step-at-a-time` (proposed) is the bound for it.
- **A daemon run is read on disk.** Its products are under the daemon's state directory (`runs/<run_id>/` and
  `workspaces/<run_id>/`, `docs/daemon-api.md`): no tool or route serves them yet, and served by the daemon the
  Products tab says "the daemon serves no files of a run yet".
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count
  read from the tree or from a command named above. The times in `CHANGELOG.md` and `docs/forge-gate.md` were
  measured on the build host or the forge and are in no record of `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
