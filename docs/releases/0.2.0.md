# sdc 0.1.5

A patch release after 0.1.4, the same day: a fix of the spec gate and the results of the nine
`release-0.1.2` runs. No protocol or binding changed; one tool's check got stricter. A source
release at tag `0.1.5`; nothing is published to crates.io and no interface is stable.
`CHANGELOG.md` lists the changes with their commits.

### What changed

- **The spec gate.** `spec.synthesize` and `spec.gate` (`sdc-tool.sh` `spec_conform`) now run the
  synthesized suite against ESS's interpreted target
  (`ess verify conform run --target interpreted --strict`). A spec passes only when every scenario
  passes; an unsupported, failed or errored scenario refuses it, and `spec.author` gets one line per
  such scenario. Before, the gate required only that synthesis refused nothing, so a spec whose own
  suite did not pass reached the story. There the implementing writer cannot change it:
  `release-0.1.2.mixed.1` stopped `writer_spent` at `change.implement` that way, with 8 scenarios
  unsupported ("binding command has an unmet outcome obligation"). The check costs about 0.04 s
  more on a baseline-size spec. Cycle `spec-interp-unsupported`; the committed replay recording is
  re-packed.
- **The results of `release-0.1.2`** (`experiments/release-0.1.2/report.md`, `notes.md`): nine runs
  on tree 72a3eef, the to-do idea in the three baseline settings.

### The release-0.1.2 runs

| setting | clean passes | `run.cost_usd`, median [min, max] | `run.wall_s`, median [min, max] | stops |
|---|---|---|---|---|
| strong (Sonnet work, Opus decider) | 3 of 3 | 4.695 [4.460, 4.816] | 972 [886, 1108] | - |
| mixed (Sonnet work, Haiku decider and other nodes) | 2 of 3 | 2.523 [1.373, 3.035] | 1577 [810, 1821] | `writer_spent` in IDEA-1.sharedlist.list |
| Haiku | 2 of 3 | 0.932 [0.882, 1.724] | 3231 [2832, 3278] | `writer_spent` in IDEA-1.list.sync |

Against `baseline-0.1.0` (same input and settings, tree 4468bfd), with the record's registered
rule: a difference is claimed only when the two ranges of three separate completely.

- **Haiku, primary (P1).** `run.clean` is 2 of 3 against 0 of 3 in the baseline. The record holds
  P1 only at 3 of 3 and calls 1 or 2 of 3 **inconclusive**, so this is inconclusive.
- **Strong and mixed clean passes (guard P4).** Strong stays at 3 of 3. Mixed fell from 3 of 3 to 2
  of 3: the guard "run.clean of strong and mixed stays 3 of 3" does not hold for mixed. Its stop is
  the spec defect that this release's gate fix refuses at the spec stage.
- **Strong cost.** 4.46 to 4.82 USD against 5.43 to 6.19 USD: the ranges separate downward. The
  notes trace 2.71 of the 3.16 USD difference to reruns: 5 rather than 12 reruns of
  `change.implement` and `spec.author`, cheaper remaining reruns, and shorter review reads. Without
  reruns the two trees overlap. No change between the trees makes a first take smaller, and with
  three runs per tree the notes call the separation most likely chance. The registered expectation
  of no separation stands for first-take cost.
- **Mixed cost** (2.523 [1.373, 3.035] against 2.55 [2.50, 3.88]) overlaps; no claim.

  `sdc-experiment check --all`, `task docs:build` and `task docs:test`.

### Limits

- Three runs per setting and tree; every claim above follows the record's rule.
- The story's `tests.run` still runs the interpreted suite, so it repeats a check the spec stage now
  passes; removing it is a follow-up.
- The conformance observation after close is off by default (0.1.4); the `release-0.1.2` runs
  ran on tree 72a3eef, which has no observation, so they carry no conformance figure.
- No run has used the 0.1.3, 0.1.4 or 0.1.5 tree.
- The driver's runtime parts are a temporary copy of what the Loom runtime must provide.
