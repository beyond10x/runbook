# Runbook 0.14.0

A minor release of 0.13.0. One change is marked breaking: a daemon run takes a model route, named or `[route_policy]
default`, only when it has a model step, so a run whose programs all name the budget 0 takes no route and wakes
nothing. It is the first release whose release workflow builds two archives of an installed prefix, gnu and static
musl. `runbook` links Loom 0.63.0; a failed model call booked after its step ended no longer fails a run, a caller that
hangs up ends its call at the gateway, a case of a run ended at a cap shows the cap and not `Stuck`, and the bindings
checks leave out route files. A source release at tag `0.14.0`; nothing is published to crates.io and no interface is
stable. `CHANGELOG.md` lists the changes with their sources. Read `docs/releases/0.13.0.md` for the release this one
follows.

### Breaking changes

- **A daemon run takes a model route only when it has a model step.** A model step is a decider of kind `model` above
  `A0`, or a program the run's runner starts for its runbook (an `executor.argv`, an `arguments_from` or a
  `handoff_when` check) that is an agent node or reserves a per-call budget above 0; bindings that cannot be read
  count as a model step. A run whose programs all name the budget 0 took `[route_policy] default` in 0.13.0 and, on a
  stopped managed route with `wake_on_submit`, sent and booked a wake and waited for the model; it now takes no route,
  wakes nothing, runs at once, and its programs get no route file. A submit of such a run that names a route is
  admitted and takes none, where it took the named route before; its first event `runbook.submitted` names the routes
  asked for under `model_route_not_taken` with the reason "the run makes no model call". The remedy: a program that
  calls a model names a per-call budget above 0 (`--max-budget-usd`, or `max_budget_usd` of its action or file), and
  a client that read `model_route` of such a run reads `model_route_not_taken` (`docs/model-routes.md`, section 2;
  `docs/daemon-api.md`, "The route of a run").

### What this release holds

- **Release archives** (`docs/releasing.md`, "The archives"; `README.md`, "Try it"). A push of the tag runs
  `.github/workflows/release.yml`: it refuses a tag that is not the version of `runbook/Cargo.toml` and builds
  `runbook-0.14.0-x86_64-unknown-linux-gnu.tar.gz` (`scripts/install.sh` on the runner, needs glibc) and, static,
  `runbook-0.14.0-x86_64-unknown-linux-musl.tar.gz`, each with a `.sha256` file, and uploads them to the tag's
  Release. The musl job fails unless every program of the prefix is static and answers `--version` with its name and
  the release version in a plain `alpine` container; the musl `runbook` allocates through mimalloc. Every helper
  program answers `--version`.
- **`runbook` links Loom 0.63.0** (`b0a0dfda`, tag `0.63.0`; replaces `112a97e1`, Loom 0.62.1). It moves Substrate
  from 0.24.0 to 0.29.0, whose host builds for `x86_64-unknown-linux-musl`; no code of `runbook` changes with it
  (`docs/library-entries.md`, row R).
- **A late failed model call no longer fails a run** (`docs/engine.md`, "A gateway"). A failed call that the relay
  books after its step ended is named under its own step with the event `runbook.model-calls-failed` and never fails
  the run; which step failed is read from the log of the step's own case only. A step whose program exits with a
  status its bindings take as a result fails nothing by itself.
- **A caller that hangs up ends its call at the gateway** (`docs/engine.md`, "A gateway"; `docs/daemon-api.md`, the
  relay). The relay closes its request to the gateway within a second and books the call once with the `cause`
  `call-abandoned` and the `code` `caller-hung-up`, at the tokens reported so far, else at its reservation.
- **A case of a run ended at a cap shows the cap** (`docs/daemon-api.md`, "The case tree of a run"). The view `cases`
  shows a case that had not ended as `SpendCapReached`, `CallCapReached` or `WallCapReached`, where it showed
  `Stuck`; the run page labels them `LLM budget spent`, `LLM calls spent` and `wall time spent`. The specification's
  `CaseState` gains the three variants.
- **The bindings checks leave out route files** (`docs/loom-bindings.md`). `scripts/check-bindings.sh` and `runbook
  check` no longer refuse `bindings/<id>.routes.yaml` as a bindings file; `runbook check` reads it with the daemon's
  reader, and a runbook can no longer be named `<x>.routes`.
- **The daemon's run page** counts the steps that are over apart (`4 done, 2 exited non-zero, 1 ended with no exit`)
  and names the run by the last 8 characters of its id, with a control that copies the whole id (`ui/README.md`).
- **The process sample of the tests** judges a child after its `exec`, so the two cases that refuse an unexpected
  program no longer fail on a child between its fork and its `exec` (`docs/forge-gate.md`). Tests only.

### How to try it

1. Take an archive from the tag's GitHub Release once the release workflow has uploaded it: check it with
   `sha256sum --check runbook-0.14.0-<triple>.tar.gz.sha256`, unpack it, and put its `bin` on `PATH`
   (`README.md`, "Try it"). Or build from the checkout: `scripts/install.sh --prefix <absolute dir>` (release mode,
   which takes minutes).
2. `runbook serve --principal agent:<id> --runtime loom` with a `runbook.toml` that declares a route, then
   `runbook catalog` and `runbook delegate --route <route> <request-file>` (`docs/daemon-api.md`, "A delegation").
3. Check the release: `task release:check VERSION=0.14.0`, and the experiment records with
   `sdc-experiment check --all`.

### Limits

- **The archives come from a workflow that has not run on a tag yet.** This is the first release whose release
  workflow builds them. Its musl job ran once, green, on the pull request that added it (head `eb1d875f`); its gnu job
  runs only on a tag push and has not run. Until the workflow's `publish` job has ended, the Release holds the notes
  and no archive.
- **The aep and ess pins name no musl archive.** `driver/aep-pin.json` (aep 0.80.0) and `driver/ess-pin.json` (ess
  0.98.0) list gnu and darwin builds only, so `sdc-conform aep-install` and `ess-install` of the musl archive install
  the gnu build of aep and ess, which needs glibc (`conformance::platform_for` in `driver/src/conformance.rs`).
- **A wake of a managed route is booked when it is sent, whatever the gateway answers.** A wake answered 5xx,
  `no-capacity` or `target-unavailable` books `wake_cost_micro_usd` against the day's wake cap though no model started,
  so failed wakes can spend the cap and later runs wait for their route and end `stopped: route` (`docs/model-routes.md`,
  section 3). The story `a-wake-is-booked-only-when-it-succeeds` (draft) fixes it in the next release.
- **A run on a route works at `--confinement local` only.** At `linux` a delegation on a route fails at once,
  `env: 'sdc-node': No such file or directory`, exit 127, from a prefix and from a checkout; the story
  `route-runs-at-linux-confinement` (draft) waits.
- **A tree left without a move by the step that reaches a cap shows the cap word**, not `Stuck`: telling it from a
  tree with a move left needs Loom to evaluate without a step (story `a-capped-runs-stuck-tree-shows-stuck`, draft;
  `docs/engine.md`).
- **A caller that half-closes its connection and still reads is not served.** The daemon's HTTP server drops its call
  as one that hung up (`docs/engine.md`, "A gateway").
- **The install script builds on the machine it runs on and installs from the checkout it lies in.** It copies
  only files git tracks and refuses a checkout whose git cannot be asked. Two installs at once into one prefix are
  not held apart; an install from an archive lacks the links and dot files of a git checkout; a release install
  after a branch was moved from another work tree is refused until an input of the build changes; a checkout with
  the reftable format cannot be installed. `scripts/install.sh --help` has each.
- **No evaluation run was made on this code.** The records of `experiments/` ran on earlier code; this release
  claims no measured change over 0.13.0. The fifth Loom evaluation record, `parity-loom-strong-5`, is registered
  and planned: it has no run yet.
- **The relay is served on a loopback listener only.** On any other listener a run on a route does not start
  (`docs/daemon-api.md`, "The relay of a run's model calls").
- **Runbook does not read the gateway's `cost_usd`.** A call's cost is its route's declared prices, else the call is
  booked at its reservation with `cost_known: false` (`docs/model-routes.md`). The Routes view shows no calls and no
  booked spend per route: the daemon serves no count of them.
- **A generated protocol of a delegation runs only the daemon's agent node.** The programs and child runbooks of the
  catalog are not built into it (`docs/model-routes.md`, section 9).
- **The default spec check tests that a reference is there, not that the spec says what the fix does.** It reads the
  whole description, so a code path under the spec directory (a test tree named `spec/`) counts; name another
  directory with `--spec-dir` (`docs/bugfix.md`).
- **The default description writer is a program and reads no feedback.** Sent back after a refusal it writes the same
  description unless its inputs changed; `sdc-check-routes` lists this as a `not-handed` finding of `handback.describe`,
  and a model writer bound in its place gets the refusal line (`docs/reject-routes.md`).
- **A gateway of `runbook run` works at `--confinement local` only.** Under `substrate` a bound program has no network,
  so the runner refuses a gateway there by the name `gateway`. `llm-adapter-metaharness.sh` cannot take one (it
  removes every `ANTHROPIC_*` variable and starts its own proxy) and ends with exit 127 when it is given one. With an
  `http://` address at a host that is not loopback the token travels in clear text; the choice is the user's
  (`docs/loom-run.md`).
- **The forge runs no UI specs.** On 2 CPUs the UI step does not end inside the 120 s step budget (550 to 587 of 611
  tests were done when the bound ended it, measured on the build node), so a UI change is checked by the local gate
  only until the test-budget defect of `test:ui` is fixed (`docs/forge-gate.md`).
- **The rework allowance is not observed in a full run.** The cycle entries that show it, `decider-rework-spent`,
  `rework-fresh-allowance` and `implement-percause`, stay `pending` (`docs/cycles-suite.md`); no run has told a
  `rework_limit` of 2 from 3.
- **The bindings check follows Loom's decoder for the forms it names.** Five forms (`merge_budget_limit`,
  `merge_budget_zero`, `merge_budget_unrelated`, `merge_in_action`, `complex_key`) were measured to be refused by
  Loom when they were measured, at `d8944d49`; no measurement of them at a later pin is recorded, no other form is
  claimed refused as Loom refuses it, and the 1 MiB text bound of Loom's reader is not checked (`CHANGELOG.md`).
- **The slow lane `task test:loom-in-process` compares a library of `b0a0dfda` with the child binary of Loom
  `70b0e6e0`** (its sha256 is pinned in `runbook/tests/loom_run/slow.rs`); no `b10x-loom` of `b0a0dfda` was built for
  it (`docs/loom-run.md`).
- **The recorded cycles run in `docs/cycles-suite.md` is at Loom `d8944d49`.** The file's last record of the whole
  suite is 55 cycles, `40 of 40 as expected, 15 pending`; the tree holds 56 cycles and the file has no record of a run
  of all of them.
- **Only `runbook run` writes `runner.json`** (`runbook/src/loom_run/in_flight.rs`). A run of the daemon and a run
  directory an older `runbook` wrote have none, and the inspector shows them as it showed them before.
- **The line of the step in flight is not shown.** Loom pipes a bound program's output into its own process and
  returns the last bytes when the program ends (`docs/loom-run-directory.md`). The daemon's run page shows the step
  in flight and its duration, not its output.
- **`runner.json` and the start lines are what files of the run directory claim.** Under `--confinement local` a
  bound program can write the run directory, so the inspector's answer is a reading of those files, shown as text,
  and nothing decides on it.
- **A run with no money cap named is not limited in money.** `runbook run` and `sdc-experiment` start a run with
  no `--cap-micro-usd` and no `--max-llm-calls`; the daemon with `--runtime loom` is the exception, it requires its
  caps and their ceilings (`docs/loom-run.md`, `docs/daemon-api.md`). A call of unknown cost in a run that names no
  spend cap books nothing. In a run opened with a model node the printed command of a handoff runs as printed under
  a named cap too, so several steps spend from one reservation before the cap is looked at again; the story
  `handoff-under-a-named-cap-runs-one-step-at-a-time` (proposed) is the bound for it.
- **The daemon serves no evidence records and no action output of a run.** Its files under `work/` are served by the
  views `products` and `product`; the rest is read on disk under the daemon's state directory (`docs/daemon-api.md`).
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is executed,
  unless `--runtime loom` is given (`docs/engine.md`).
- **The cycles that run `change.review` and the request entries are not observed as `expected` here.**
  `docs/cycles-suite.md` says that no entry changed from expected to another state is not observed on the host
  where they were run; it needs one run of the suite at a load where a cycle ends inside Loom's 60 s bound, and
  that run has not been made.
- **No statement about speed, quality or cost goes beyond `experiments/`.** A figure in these notes is a count
  read from the tree or from a command named above. The times in `CHANGELOG.md` and `docs/forge-gate.md` were
  measured on the build host or the forge and are in no record of `experiments/`.
- **The inspector is read-only and has no route to the daemon** (`ui/README.md`).
- **`--confinement local` is unconfined** (`docs/loom-run.md`): a bound program can write the whole run directory.
- `task check:ess-suite:slow`, the slow lane `task test:cycles-loom`, `task test:install` and `task docs:test` were
  not run for this release.
