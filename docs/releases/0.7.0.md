# Runbook 0.7.0

A minor release of 0.6.0, the same day. The old driver runtime is deleted: a run is `runbook run`, and
the runtime is Loom's. A refusal of Loom ends a run with the outcome `refused`, exit 12 and a named
`cause`. `runbook test` takes `--workers` and `--only` through Loom's own selection. Loom `db2726ff` is
linked. A source release at tag `0.7.0`; nothing is published to crates.io, there is no binary asset and
no interface is stable. `CHANGELOG.md` lists the changes with their sources. Read
`docs/releases/0.6.0.md` for the release this one follows.

### What this release holds

- **The old driver runtime is gone.** The binary `sdc-drive` (`driver/src/main.rs`),
  `scripts/run-trial.sh`, `scripts/run-finding-cycles.sh`, `scripts/run-full-cycle.sh`,
  `scripts/watch-run.sh`, `bindings/tools/llm-node.sh` and `bindings/tools/decider.sh` are deleted, with
  what only they used: `sdc-unstick` and its instructions, `cycles/suite.yaml`, the parity tests of the
  decider, `watch/tests/e2e.sh` and the scripts of the adversary evaluation under `eval/`
  (`eval/reports/` and `eval/baseline.json` stay as the record). A run starts with `runbook run`; the
  model step is `sdc-node` and the decider is the Rust decider of `runbook run`; the file watcher is
  `runbook run --watch`. The documents, the website, the plugin skills and `AGENTS.md` say so.
- **The package `sdc-drive` is `sdc-tools`.** `driver/Cargo.toml` names it; the library is still
  `sdc_tools` and the helper programs keep their names (`sdc-node`, `sdc-reply`, `sdc-findings`,
  `sdc-bugfix` and the rest). `docs/driver.md` says what `driver/` is now.
- **The producer ids of the bindings name the runner.** `runbook`, `runbook.build`, `.deploy`,
  `.monitor`, `.merge`, `.inspect` and `.falsifier` replace `sdc-drive` and `sdc-drive.<action>` in
  `bindings/*.yaml`, `driver/examples/**` and the generated `website/data/protocols/*.json`
  (`driver/tests/producer_ids.rs` holds the tree to it). Records of past runs keep the old id.
- **The tree suite replaces the old cycle suite.** `cycles/tree-suite.yaml` is run by `runbook test`
  (`task test:cycles-loom`, `ONLY=<name>[,<name>...]`). `runbook check` compares it with
  `cycles/old-suite-names.txt`, the committed list of the 130 entries of the deleted suite, and with
  the rows of `docs/cycles-suite.md`.
- **Loom `db2726ff` is linked** (it replaces `70b0e6e0`; version 0.59.0, a merge on a branch of the
  engine, in no tag). An action is dated by the revisions its own step left: the amend step is taken
  again after a check that failed following a later write. The tree suite was run again at this pin:
  `run-stop`, `replay-sibling` and `decider-rework` run as expected and lost `pending`.
- **A refusal of Loom ends a run by name.** The outcome `refused` (exit 12) carries the member `cause`
  in `outcome.json`, in the `ended` event and in `run-stopped.json`, one `cause` for each of the 29
  reasons of `TreeRefusalReason` and one for a program the engine's runner ended by a signal
  (`runbook/src/engine/refusal.rs`; `docs/loom-run.md` has the table and the list). A held tree
  (`tree hold`) is refused by name, and runs again once it is reopened (`runbook/tests/loom_run/held.rs`).
- **`runbook test --workers N` and `--only`.** `--workers` is 1 to 64 (default 1) and goes to Loom's
  suite runner; more than 1 under `--confinement substrate` is refused (exit 2); a value outside the
  range is exit 64. `--only` is Loom's selection: a name that is no cycle is Loom's `CycleUnknown`,
  and the closing line says `selected S of C cycles`.
- **`scripts/check-bindings.sh` checks more.** It fails when the two copies of a binding (`bindings/*.yaml`
  and `driver/examples/sdc/*.bindings.json`) differ in their leading `argv` members or in what the route
  check reads, and it reads the block `runtime` of `driver/examples/sdc/rule-ends.json`, which says who
  holds each capability in a run on Loom (`loom:`, `runner:` or `absent:`, each with a `file:line`). It
  finds 36 routes (it found 15).

`runbook --version` prints 0.7.0.

### Breaking

- **Removed programs and scripts.** `sdc-drive` and `scripts/run-trial.sh` and
  `scripts/run-full-cycle.sh`: use `runbook run`. `scripts/run-finding-cycles.sh` and `task
  cycles:only`: use `runbook test cycles/tree-suite.yaml` (`task test:cycles-loom`).
  `scripts/watch-run.sh`: use `runbook run --watch`. `bindings/tools/llm-node.sh`: the bindings start
  `sdc-node`. `bindings/tools/decider.sh`: the decider is in `runbook run`. `sdc-unstick`,
  `task test:decider-parity` and the adversary scripts of `eval/` have no replacement. `runbook doctor`
  no longer lists `canon`, `sdc-drive`, `sdc-unstick`, `rsync` or `bindings/tools/decider.sh`.
- **The package and the producer ids.** `sdc-drive` is `sdc-tools` in `driver/Cargo.toml` and in the
  lock files (a script that reads the package name changes). The producer ids of the bindings are
  `runbook` and `runbook.<action>` (a reader that matches `sdc-drive` in a binding or in the site data
  changes).
- **Three refusals are exit 12.** `ConfinementRefused`, `PersonProgramFailed` and `NotAPersonAction`
  ended a run `error` with exit 1; they end it `refused` with exit 12 and their `cause`
  (`confinement_refused`, `person_program_failed`, `not_a_person_action`). So does every other
  refusal of `tree open`, `tree run` and an answer that leads with a reason name (`StoreNotEmpty`,
  `UnknownProtocol` and the rest). A caller that reads exit 1 for them changes. Exit 2 stays a refusal
  before a run directory exists; `tree status` and `tree verify` refused after the run stay exit 1.
- **37 entries of the old cycle suite are dropped.** The entries tested the driver's own autopilot loop,
  `--keep-going`, the unstick step, the rule approver, stand-in binaries through the environment or a
  second tool reading a finished run; `docs/cycles-suite.md` names each one. The other 93 are held:
  40 converted and 14 pending in `cycles/tree-suite.yaml`, 39 by Rust tests of the runner.

### How to try it

There is no binary to download: build from the checkout (`README.md`, "Try it"). Each `--help` below was
run on this tree.

1. Build: `cd driver && cargo build --locked --bins`, then `cd runbook && cargo build --locked --bin
   runbook`. `runbook --version` prints 0.7.0.
2. `runbook run --help` prints the options of a run; `docs/loom-run.md` has the exit codes and the
   table of the `cause` of a `refused` run.
3. `runbook test --help` lists `--workers` and `--only`. `task test:cycles-loom ONLY=stub-cycle` runs
   one cycle of the tree suite with no model call (a slow lane; start it in the background).
4. `runbook check` checks the text layout, the bindings, the instruction files, the views and
   `cycles/tree-suite.yaml` against `cycles/old-suite-names.txt` and `docs/cycles-suite.md`.
5. Check the release: `task release:check VERSION=0.7.0`, and the experiment records with
   `sdc-experiment check --all`.

### Numbers

- The bindings hold 14 model nodes, all started through `sdc-node`.
- `cycles/old-suite-names.txt` lists the 130 entries of the deleted suite. `cycles/tree-suite.yaml`
  holds 54: 40 converted and 14 pending (37 and 17 in 0.6.0). 39 entries are held by Rust
  tests and 37 are dropped (`docs/cycles-suite.md`, "Totals and time").
- 15 Rust tests are `#[ignore]`d in the default test step (16 in 0.6.0, one of them in the deleted parity
  tests of the decider); each names the slow lane that runs it (`task test:replay` for nine of them).
- 29 reasons of `TreeRefusalReason`, each with its own `cause`.
- `scripts/check-bindings.sh` finds 36 routes.
- The tests of this code ran green on the forge for the merge commit `826b09c7`, the base of this
  release (the four runs of that commit: Shared source gates, Protocol checks, Documentation validation
  and Documentation site). No count and no time of a test step is claimed here: the machine that
  prepared this note ran none (its load average was above 120).

### Limits

- **No evaluation run was made on this code.** The three runs of record
  `experiments/parity-loom-strong-4.yaml` ran on the code of 0.6.0 and delivered 0 of 3; all stopped
  `stuck`. Two of the causes the record names are not fixed in this release. A model node that is not
  called (a finding waits for a person, or the decisions it would follow are the defaults) exits 0 and
  still counts against `budget.max_runs` at Loom `db2726ff` (run 1 stopped at `spec.author`, run 3 at
  `change.implement`; `bindings/PENDING.md` names the missing not-called exit of the bindings). And a
  rejection gives the writer no new allowance of runs: the cycles `decider-rework-spent` and
  `rework-fresh-allowance` still fail on `RunsSpent` (`docs/cycles-suite.md`). The cause of run 2 (an
  action dated by the next `evaluated` line) is what `db2726ff` changes; a no-model test
  (`runbook/tests/test_suite/amend.rs`) holds that state and a run of it ends `passed`, but no
  evaluation run has used it.
- **No statement about speed, quality or cost goes beyond `experiments/`.** The release claims no
  measured change over 0.6.0 or over the old driver; a figure in these notes is one that a record of
  `experiments/` carries or a count read from the tree.
- **The old driver's records keep its names.** Records of past runs (`cases/**/evidence`,
  `experiments/`, the recorded run of `ui/test/recorded/`) keep the producer id `sdc-drive`, and the
  record `parity-loom-strong-4` names files that are deleted now.
- **The cycles are not all converted.** Of the 130 entries of the old suite 40 are converted, 14 are
  pending, 39 are held by Rust tests and 37 are dropped. The whole file is a slow lane,
  `task test:cycles-loom`; it was not run on this tree for this note, and `docs/cycles-suite.md` says
  that cycles run at a one-minute load of 100 to 177 ended on Loom's 60 s wall bound (11 entries).
  The replay entries are Rust tests of the slow lane `task test:replay`, not run for this note either.
- **`sdc-experiment` does not carry an effort.** It refuses `efforts.*` in a `loom` variant: the record
  format does not carry an effort to the runner yet, so the class defaults apply to a run it starts.
  `sdc-node --effort` and the settings file of `runbook run` do carry one.
- **The daemon runs a stub unless asked.** `runbook serve` runs the stub runtime, in which nothing is
  executed, unless `--runtime loom` is given (`runbook/src/serve.rs`, `docs/engine.md`); the daemon's
  default confinement floor is `linux` and `local` must be asked for by name
  (`docs/daemon-api.md`). The Loom runtime is run through the slow lane `task test:engine-real`, not
  by the gate.
- **`--confinement local` is unconfined.** `local` is "unconfined and declared insecure"
  (`docs/loom-run.md`): a bound program can write the whole run directory, including the copy of the
  routing table (the runner reads it once, so a rewrite changes no routing), the decider's
  instruction files and adapter, and the replay plan and call log. Under `--confinement substrate`
  the run directory is out of a bound program's reach (`docs/loom-run-decisions.md`).
- The rule approver (`SDC_RULE_APPROVALS`, claims of the position), the rework cap of the old driver
  and the end by rule `withhold` are not in the runner: Loom's output holds no claim values and Loom
  has no such steps (`docs/loom-run-decisions.md`).
- `task check:ess-suite:slow`, the byte comparison of a new synthesis with the committed suite, and
  `task docs:test` were not run for this release; the fast digest check is part of
  `task check:ess-generated`.
