# sdc 0.1.1

A patch release after 0.1.0, the same day: the reject and cap routes of the audit, ways to keep a
trial run going and to reopen it, a static route check and a pinned `canon simulate` step,
workflow metrics with experiment records and a progress ledger, recorded replay, and the live
view's run picker. No protocol of the nine changed. A source release at tag `0.1.1`; nothing is
published to crates.io and no interface is stable. `CHANGELOG.md` lists the changes with their
commits.

### What changed

- Reject and cap routes (`docs/reject-routes.md`): a writer's failed run is fed back to its next
  run (R9), a writer's runs are capped per retry kind (R7), a failed check's own output reaches the
  writer (R13), an unattributed scope-changing answer goes to the decider as a question (R2), and a
  refused finding decision is asked again with the refusal (R3). `sdc-check-routes` checks the
  routes statically from `scripts/check-bindings.sh`; its 15 findings on this tree equal the list
  in the doc.
- Trial runs: `--keep-going` forces past autopilot's stops and records each defect in
  `defects.jsonl`; `run.unstick` picks a legal move before a stop that is no cap (default effort
  `xhigh`); `--reopen` runs a step that recorded nothing once more on the unchanged state.
- `sdc-bugfix`: the reproducing test is attributed by its own run (the red-check defect named in
  the 0.1.0 limits), three more seeds, four scripted cycles.
- `scripts/check-protocols.sh` runs `canon simulate` with Canon pinned at release `0.10.0` (commit
  `2c7a1ea6`) and compares each protocol's report with `protocol/simulate/<name>.txt`: 71
  findings on the eight cycle protocols, the same as on the earlier unreleased pin `a1a937ec`, and
  0 on `sdc-bugfix` (11 reachable states, 5 terminable).
- Measurement: `sdc-run-metrics`, experiment records under `experiments/` launched and checked by
  `sdc-experiment`, and the progress ledger `docs/progress.md` with its image
  `docs/img/progress.svg`.
- Recorded replay: `scripts/run-trial.sh <run> --autopilot --recorded <source>` re-drives a
  recorded run with the real driver and programs and the recorded model replies; a stub recording
  is committed under `driver/examples/sdc/fixtures/recorded/stub`, re-packed on this tree. A
  recording made before effort-per-class diverges at its first call on 0.1.1 and later (the
  request now carries an effort); recordings are re-packed after a change to the request shape.
- The live view picks a run by search, grouped by experiment.

### A defect in a figure tool

`sdc-run-compare` left out the cost of every decider call whose escalation was suppressed: for
`trial-3-haiku-9` it reported a decider cost of 0.159 USD where 0.325 USD was spent. The live
view's KPI strip had the same rule. Both now count every decider call made, once per record, at
the highest `cost_usd` among that record's lines (`df58754`, `9ff2996`). `sdc-run-metrics` and
`sdc-experiment` counted it right, so the experiment records and the progress ledger are not
affected. Figures of the 0.1.0 notes that came from `sdc-run-compare` are corrected in a later
release.

### Checks on this tree

- `scripts/run-finding-cycles.sh`: 96 expected cycles and 2 pending (`rework-spent-dropped`,
  `rework-spent-abandoned`, routes not built yet, which never fail the script), counted from the
  script's `expected` and `pending` arrays.
- `scripts/evaluate-cases.sh`: 52 situations in 12 fixture cases.
- `sdc-experiment check --all`: every record, report, verdict, `experiments/INDEX.md` and the
  progress ledger current.

### Limits

- No run has used this tree. The progress ledger's figures come from runs on earlier trees, and
  the baseline on a released tree (n of at least 3 per setting) is still to be run.
- The rework limit lives in `driver/examples/sdc/rule-ends.json` (`rework_limit`, 2), but
  `sdc-replay --set max_rejections=<n>` and the rework prompt still read `SDC_MAX_REJECTIONS`.
- Nobody started the delivered product.
- The driver's runtime parts are a temporary copy of what the Loom runtime must provide.
